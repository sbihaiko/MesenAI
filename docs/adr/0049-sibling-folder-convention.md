# ADR-0049: Convention over configuration — the sibling folder is the pack

- Status: accepted (F5.1, 2026-08-25)
- Date: 2026-08-25
- Phase 5 (docs/roadmap/plano-execucao-F5.md). Supersedes the manifest-heavy drafts of ADR-0045/0046/0048 (deleted 2026-08-27; text in git history).
- Amended by: ADR-0243 (accepted 2026-10-02, slice F12.20, not implemented) — the bootstrap stops running by itself in Play (*Bootstrap enhancement folder for played games* defaults to off for new installs), records into `auto/rec-NNN/`, and may record while the project's own `mep/` dresses the ROM.
- Amended by: ADR-0147 (the human layer moves from the pack root to `mep/`), ADR-0160 (`Chr_XX_N.png` leaves the pack root for `textures/chr/`)
- Related: ADR-0040 (storage/discovery precedence), ADR-0050 (bootstrap backgrounds written into the sibling folder), ADR-0146 (an accepted community pack wins over the local auto-only pack)

## Context
Two real packs (Contra80s, Zelda Remastered) showed authors fighting text manifests and coordinates. The direction: fewer mappings, more conventions.

## Decision
### 1. Location and identity
For `<dir>/<Game>.nes` the pack is `<dir>/<Game>/`. No `pack.json` needed: the host derives the target hash and the system from the ROM beside it. A `pack.json` is **optional**, adding metadata (name, author, license, extra `targets[]`) only when the folder is published as a MEP zip — `mep pack` writes it.

**The local folder always wins.** ADR-0147 (2026-09-01, `3bc4482d`) splits the layout into `auto/` (recorder) and `mep/`. Discovery order (revises ADR-0040): **sibling folder** `<dir>/<Game>/` → `HdPacks/<Game>/` (legacy) → `EnhancementPacks/` containers (folders and zips). If the ROM's directory is unwritable, the bootstrap goes to `EnhancementPacks/<Game>/` and a notice says so.

**Zip = the folder, zipped.** `<Game>.zip` (the sibling folder zipped as-is, no `pack.json`) is accepted in `EnhancementPacks/`, matched by the same rule: name equal to the ROM's name. `pack.json` remains optional metadata for publishing (hash-based matching for any file name, credits, license); `mep pack` writes it.

### 2. Fixed layout — the folder tree is the manifest
`<Game>/` = top-level artist layer (`textures/` with `hires.txt`, `sheets/`; `audio/` with `bgm/<track>.ogg`, `sfx/`, `midi/`, `stems/`; `synth/preset.cfg`) plus a machine layer under `auto/`; `.bootstrap` records generator version + ROM sha1.

- Canonical minimal layout = MEP-v1 §2.1 rule 6 (`textures/hires.txt`, `audio/hires.txt` or `audio/fingerprints.json`, `synth/preset.cfg`, and their `auto/` mirror). `textures/hires.txt` "generated by `mep build`" is author-side tooling; host automation (bootstrap/regeneration) only writes inside `auto/`, which is how the tree coexists with rule 6 ("everything outside `auto/` belongs to the author and MUST NOT be altered by automated tools").
- The extra folders (`sheets/`, `midi/`, `stems/`, `.bootstrap`) are authoring material hosts ignore.
- **Two layers, by folder**: top-level = human (`art`), `auto/` = machine. Precedence per entry: top-level > `auto/`. No layer ids, no toggles beyond "use auto layer" (global) and "use sibling packs" (global). *Open tension:* MEP-v1 §5 requires a toggle independent per section; whether the sibling-folder pack is exposed with the usual per-section toggles (ADR-0040's model) or §5 gains an exception is still to be decided.
- **Provenance by location**: a file under `auto/` is machine-made; a file outside it is human-made.
- **Names are keys**: `bgm/<track>.ogg` maps to the `<bgm>` entry of the same track id; `sheets/<object>.png` cells map to tile keys through the sheet's order.

### 3. Trigger
Setting *"Bootstrap enhancement folder for played games"* (default **on**). On load, if `<Game>/` has no `.bootstrap` or its generator version is older, the emulator exports ROM tiles (ADR-0043), records tiles + MIDI/VGM while the user plays (rolling, bounded), and on unload/power-off runs the auto steps (upscale, segment, fingerprint, render) into `auto/`. Second load already plays with the auto layer; everything human stays untouched.

## Consequences
- The folder is the *authoring* form, the zip the *distribution* form; both load, the folder wins over any installed zip.
- Name-based matching is deliberately looser than hash matching — the trade-off the legacy `HdPacks/<rom>/` makes.
- Library folders get one subfolder per played game; the setting turns it off.
- Rendering audio needs external tools (fluidsynth); when missing, `auto/audio` gets MIDI only.
