# ADR-0209: Name a figure, hand it to the artist's own editor, and reload — MesenAI owns selection and coverage, not the brush

- Status: accepted
- Date: 2026-09-18 (amended 2026-09-19, 2026-09-20, 2026-09-22, 2026-09-24, 2026-09-25)
- Related: ADR-0003, ADR-0145, ADR-0153 ("artist-legible sheets"), ADR-0154, ADR-0156, ADR-0164, ADR-0165 (the composition editor), ADR-0168 (the `sprNNN` figure is the sprite unit), ADR-0169 (read-only record viewer), ADR-0178, ADR-0183 ("an observation, never a reading"), ADR-0198, ADR-0210 (where sheet coverage comes from; amends Q4(m)), ADR-0212, ADR-0213, ADR-0225, PRD Part A F12.2 (code on `main`), F12.3 (reload), F12.4 (asset-name template); PRD Part A F12.9/F12.12 for the coverage sources

## Decision

The paint loop is four steps — work on the screen at high resolution, **mark a figure** and open it in the artist's own paint program, edit and save, reload and look. MesenAI owns **selection** (which art, named) and **return** (the edited file coming back and rendering); it delegates **painting** to the program the artist already uses.

1. **Q1 = (b): the Core writes `label`.** At record time it infers a default `label` from the grouping it computed (`metatile`, `context`, `count`), beside `"labelSource": "inferred"` — on every sheet cell (`<context> #<metatile> x<count>`), every `sprNNN`/`objNNN` group sheet (`<kind> group <cols>x<rows>, <n> cells[, <p> poses], x<max count>`), every `poses.json` pose (`figure <w>x<h>, <t> tiles, <f> frames[, fusion][, variant of poseNNN]`) and run (`<loop|sequence> of <n> phases, <w>x<h>, x<repeats>[, driver portN]`). The scheme is `Core/NES/HdPacks/SheetLabels.h`, host-free, and states only what the recording measured (ADR-0183 §3/§5). Readers (`scripts/compose_engine.py` `caption()`, `scripts/artist_kit.py` captions, `scripts/mep_figure.py export` `label`/`labelSource`, with `--names`) prefer a human `names.json` name, then the sidecar `label`, then the id. An artist renames by editing the sidecar's `label` and `labelSource`.

2. **Q2 = (e): "mark a figure" exports the figure** (the `sprNNN` unit of ADR-0168, or an `objNNN` group), reassembled through its `evidence[]` offsets into one PNG the artist sees as a character rather than as fragments. `scripts/mep_figure.py export` writes it plus its 1x `*.orig.png` twin and a sidecar mapping each cell rect to `(sheet, cell index)`, on the F12.4 asset-name contract (ADR-0213).

3. **Q3 = (i): the file returns however F12.4's template already decides**, this ADR adding only the launch and the F12.3 reload trigger (ADR-0212). `scripts/mep_figure.py import` brings the painted file back onto exactly those cells, only where they differ from the twin, with `--verify` as the ADR-0183 §4 round-trip. `import` writes each painted cell where the pack's built `hires.txt` already draws its key from — on a kit project the untouched `usrNNN` row, not the `sprites.png` cell the figure sidecar names — so the rebuild leaves `hires.txt` byte-identical and the F12.3 reload shows a kit figure (`usrNNN-figure`, `poseNNN`); an import that still has to re-point a key says so (#413).

4. **Q4 = (k): the `unsorted` remainder sheet**, chosen 2026-09-19 and shipped as F12.8. `unsorted.png` / `unsorted.orig.png` / `unsorted.json` carry one 8x8 cell for every recorded shape no other sheet put on a canvas, written last in `HdPackBuilder::BuildSheets`. `WriteSheetFiles` is the single funnel every sheet passes through, so it accumulates the shape ids and the remainder reads what is left; coverage of the recorder's shape registry becomes 100% by construction. Not alias-collapsed (`CollapseAliases` would hide a key behind a look-alike); a shape with no drawable art is left off, never a transparent cell that resolves to empty pixels; an empty remainder writes no file. Same `BuildContactSheet` geometry, same `*.orig.png` twin, same v1 sidecar; `mep_build.py build` reads it with one `_SHEET_RANK` entry of 0.

   **Q4's other options, and why (m) is not this ADR's problem.** (j) record more — the only thing that adds *observed* pairs, never *reaches* 100%; (l) leave it and keep `Copy as MEP sheet cell` as the escape hatch — what (k) supersedes. (m) proposed seeding coverage from an existing pack's key index on the premise that a `<tile>` key is `(tileData, palette)`: "16 bytes of original CHR" plus four NES colors — that *is* the original art. Half true: `HdPackLoader::ReadTileData` branches on length — 32 hex characters or more is the literal 16 pattern bytes (a CHR RAM game, the art genuinely in the key), anything shorter is a tile index into the ROM's own CHR and carries no art (a CHR ROM game) — so for 23 of the 30 bounded ROMs a third-party index contributes palettes only. Provenance is recorded in `pack.json`. ADR-0210 decides how each source is used. `mep_import.py` is **not** (m): ADR-0198 §1 has it cut every `<tile>` it names out of the PNG the rule points at, while the shipped `scripts/mep_import.py index` imports the index and leaves the art alone, filtering through `Rule.parsed_index(ver)`. A pack carrying `<patch>` keys the *patched* ROM's namespace (ADR-0198 §2/§3), so it cannot seed anything without §3's guard.

### What (k) closed, and what it did not (measured 2026-09-19)

Run on two CHR RAM games (Castlevania 60 s idle; Zelda 85 s from `scripts/stages/zelda/mint-stage1.txt` + `stage1-run.txt`). (k) closes the gap between the shape registry and the sheets completely — Castlevania 380→514, Zelda 187→277, **100% by construction** — but not the far larger gap between the *pack* and the registry: pack coverage after is 19.2% / 17.2%. The cause is upstream of every sheet: `ShapeIdFor` (the only thing appending to `_shapeTiles`) is reached only from `RecordGridFrame` and `RecordSprite`, both gated on `_captureScreens` and fed by the retained frame stream (`kMaxSheetFrames`), while `HdPackBuilder::ProcessTile`, which emits the `<tile>` rules, runs on everything the PPU draws. Zelda's registry tops out at shape id 276 while its `hires.txt` names 1 615 distinct shapes, so the missing 1 338 were never offered to the sheet pipeline. Reaching 100% of the pack is a separate decision about what the recorder retains, left open here.

### The figure sidecar's optional `mirror`

Amended 2026-09-25 (#463, PR #482): the figure sidecar's per-cell entry gains one optional field, `mirror` — one `"H"`/`"V"`/`"HV"`/`""` per 8x8 sub-tile in `tiles[]` order, written by `export` only when the cell's home crop still carries an ADR-0178 §4 `mirror`. The first `mep_build.py build` un-bakes the crops and drops the sheet sidecar's `mirror` (#255), so the figure keeps the only record of the flip its pixels were cut in. `import` un-bakes the paint (and the ADR-0225 §3 ownership mask) by that flip and reports `unmirrored`. A figure without the field imports as before; readers must treat `mirror` as optional.

## Context

F12.2 shipped *Copy as MEP sheet cell* on 2026-09-17; the four-step request came from the chair before the panel reached its paste step, which copies a key into `misc.json`, finds pixel `208,276` on `misc.png` and on Contra resizes two canvases.

What exists: `map-000.png` in a Zelda pack is 2048x704 at `<scale>` 4 (`MesenSheets::Upscale(image, _hdData.Scale)` in `HdPackBuilder`), the surface of ADR-0153/ADR-0156; grouping (`metatiles.json` — Zelda, `count` 1 004 on the first cell; `obj000..007.json` with `kind: "object"`; `sprites.json`; the `sprNNN` figure of ADR-0168); `label`, emitted empty by `Core/NES/HdPacks/SheetRender.cpp` as `", \"label\": \"\", \"tiles\": "` and read by nobody; F12.3 (reload without reopening the ROM), measured by F12.1 at a 412 ms parse against a 13.2-16.4 s detached decode of 271 images (`HdPackData::LoadAsync`). Our own tools cannot be the brush: `scripts/compose_editor.py` (ADR-0165) composes — it places art, it does not draw it; `scripts/record_viewer.py` (ADR-0169) is read-only; `scripts/sheet_repaint.py` is a *generated* upscale into `auto/repaint/`, labeled `generated` so ADR-0154 keeps it out of the catalog.

Measured 2026-09-18: every `<tile>` rule points at `chr/`, none at `sheets/` (Zelda 2 203 of 2 203, Contra 2 276 of 2 276). A cell already in a sheet therefore works today — open `sheets/metatiles.png`, paint, `mep_build.py build` (which asks "was this cell painted?" against its `*.orig.png` twin, `_EditedProbe`, and rewrites `hires.txt`), reopen — but the sheets hold 319 keys against the pack's 2 203 (275 matching, 12.5%); the answer to "why are the editable textures not already in `auto/`?" is "they are, for one tile in eight", leaving 1 928 keys with no sheet. Those keys are not CHR noise: `HdPackBuilder::ProcessTile` is called from `HdBuilderPpu` per scanline and cycle, so a tile is recorded only when the PPU drew it. The split between "art we already have in a PNG" and "art we never recorded" does not bear on feasibility, only on where the pixel comes from: since `tileData` is in the key, both are generated the same way.

Constraints, binding on every option: the process must be simple (the four steps are the budget, not an aspiration); feedback must be **in the game** — the artist sees the change in the running game, not a rebuilt PNG or a lint exit; returning to the same moment is in scope — if reload cannot preserve it, the emulator may save the state, reload and restore it. Constraint 3 settles F12.3: save-state / reload / restore satisfies "with no state loss" without per-image invalidation, at the price of a visible pause. Two things make that price smaller than it looks, but a save state carries console state, not pack state, so pixel exactness after restore is the test, and "it looked right" is not it. Without reload, step 4 is "reopen the ROM", the friction the whole request exists to remove.

Non-goals: writing a pixel editor; reading `.psd`; changing the recorder's scale; superseding F12.2 (`Copy as MEP sheet cell` stays the escape hatch and the panel's baseline).

## Consequences

- **(f) screen-crop export is the expensive answer**: a stroke spanning cells is resolved by nothing in `mep_build` today, which paints per cell against an `orig` twin. Both (f) and (c) also add a decision the artist has to make before they can paint — a stroke spanning cells cannot be resolved, and constraint 1 rejects that on its own.
- Launching an external program is a per-platform affordance (`open -a`, `xdg-open`, `ShellExecute`) and the first place MesenAI would execute something the user configured.
- (k) grows every pack's `sheets/` by whatever the vocabulary did not claim (Zelda: 1 928 keys against 319); its size, and whether one sheet or many, had to be measured.
- Filling `label` changes a constant field; a reader written against "label is always empty" would break — there are none today, which is why this is cheap now and will not stay cheap.
- A kit figure (`usrNNN`) whose key another sheet owns is covered by the #413 fix; the ADR-0212 non-goals and ADR-0153 §4 (painted beats untouched) are unchanged.
