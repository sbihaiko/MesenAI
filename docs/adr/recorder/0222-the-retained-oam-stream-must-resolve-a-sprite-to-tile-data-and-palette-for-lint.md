## Decision

**The retained OAM stream (`MESEN_OAM_STREAM_DUMP`, `HdPackBuilder`) is self-describing** exactly as the grid stream (`MESEN_SHEET_GRID_DUMP`, `HdPackBuilder::WriteGridDump`) is: shapes are interned with `K <id> <32 hex tile data> <8 hex palette>`, palette words with `P <id> <8 hex palette>`, and each entry is `<shape>,<x>,<y>,<pal>` — `shape` the `ShapeId` `RecordOamEntry` already holds (`OamEntry::Shape`, interned by `HdPackBuilder::ShapeIdFor` / `tile.GetKey(true)` into the shared `_shapeTiles`, palette-wildcarded), `pal` the interned palette word of the sprite's OAM attribute bits (`kUnknownPalette` has no `P` line). Both streams are capped at `kMaxSheetFrames`; a grid cell line is `<x> <y> <shape> [<palette id>]`. `OamEntry` gains that palette id and `SameEntries` / `operator==` compare it, so frames differing only in sprite color no longer collapse. `OamEntry` was `{Shape, X, Y}`; `spriteNearby` carries `tileData` **and** `palette` (with an optional `ignorePalette`). The frame prefix stays `<frame> <repeat> <port1> <port2>` (ADR-0181). `mep_conditions.py` gains `parse_oam_dump` beside `parse_grid_dump`, so `spriteNearby`, `spriteAtPosition`, `positionCheckX/Y`, `positionCheck*` and `originPositionCheckX/Y` get a verdict from the OAM file alone, and `memoryCheck` reads its second operand from the `M <4096 hex>` plane as `memoryCheckConstant` does. The old `node` token is retired (`<node>,<x>,<y>`, `vocab.Find(key)`); `scripts/stages/README.md`'s dump-format sentences must follow in the same PR — its "node,x,y per sprite" and its ("`node,x,y` per sprite").

1. **`OamEntry` gains `BehindBg`, `VisiblePixels` and `HiddenPixels`** — OAM attribute bit 5, pixels put on screen, pixels an opaque background took. None is identity: `operator==`/`SameEntries` unchanged, so frame de-duplication and existing frame counts stay. `OamFetchLatch::Decode` fills `Half::BackgroundPriority` from bit 5; `Half` carries it to the record.

2. **The pixel tally.** `NesPpu<T>::GetPixelColor` calls `((T*)this)->NoteSpritePixel(spriteColor, backgroundColor, backgroundPriority)` on the one dot the original return would have drawn; the return below it is byte-for-byte the original. `BaseNesPpu::NoteSpritePixel` is an empty `__forceinline` (`GetPixelColor`, `BaseNesPpu.h`); `HdBuilderPpu::NoteSpritePixel` is the only override — the classes that never look at a mask (`NsfPpu`, `DefaultNesPpu`, `HdNesPpu`) do not — classifying through `MesenSheets::SpritePixelVerdictOf(spriteColor, emulatorSpritesEnabled, backgroundColor, backgroundPriority)` in `TileSheetTypes.h`; `HdBuilderPpu::DrawPixel` hands the verdict to `OamFetchLatch::OnSpritePixel(x, tileBase, top, verdict)`. It is *not* readable off `_lastSprite` (the highest-priority **active** shifter, set before any `currColor != 0` test). An earlier form put a `NesSpritePixelVerdict` on `BaseNesPpu` read by `if(_emulatorSpritesEnabled && ...)` — rejected for the per-dot store. The tally is per frame, saturating, bounded by `SlotCount`, keyed by `OamFetchLatch::SpriteId {X, TileBase, Top}` (the identity `SpriteFetchLog` uses, PR #476); the caller reports only a dot an OAM entry can be placed on (`SpriteRowIsPlaced`, #479), and two halves sharing an identity can only make a mask look less hidden.

3. **The rule, its scope, its threshold.** A tile's appearance is hidden iff

   ```
   that entry is behind the background
     &&  it contended for pixels and lost at least one to the background
     &&  it put none of them on screen
   ```

   i.e. `IsMaskEntry(behindBg, visiblePixels, hiddenPixels)` = `behindBg && hiddenPixels > 0 && visiblePixels <= kMaskMaxVisiblePixels`, the one predicate in `TileSheetTypes.h`. The scope is the **pose**: `SegmentFrame` records each tile's visibility, `BuildPoses` accumulates per cluster whether each tile ever showed, and a tile leaves a pose when it never did — the reduction `LinkPoseTracks` also applies. `kMaskMaxVisiblePixels = 0`, because the priority bit that lets a pixel through is the bit the rule tests. `hiddenPixels > 0` separates "the background hid it" from "the PPU never drew it" (the 8-per-line limit, Punch-Out!!'s second pass). Measured: no label moves — SMB3 2, Castlevania 0, Punch-Out!! 88.

4. **Where it is applied.** `SegmentFrame` segments one appearance per record (`X`, `Y`, `Node`, `Shown`), not parallel vectors. An artless placement (`Node < 0`, issue #520 / PR #526) is `Shown`, because `IsMaskEntry` needs `hiddenPixels > 0`. `PoseCluster::Visible` and `PoseCluster::ArtlessCells` carry visibility and the placement cells out; `PoseVisibility` is the whole-recording record; `VisiblePoseTiles` the reduction for `BuildPoses` and `LinkPoseTracks` (a tile with no flag is kept). The floor is re-applied on the union of the figure's cells (`PoseCellCount`), never the surviving tiles. Nothing leaves the vocabulary or the sheets; `adjacency.json` gains `behindBgAppearances`, `maskAppearances`, `visiblePixels`, `hiddenPixels` and `mask` per node (`SheetRender.cpp`); `mask` is `SelectMaskNodes`' label — evidence, not "this shape left a pose".

5. **The dump format.** The entry becomes `<shape>,<x>,<y>,<pal>,<visible>,<bg>,<hidden>` — additive, per this ADR's self-describing shape. A pre-ADR-0234 dump parses unchanged (`scripts/mep_conditions.py`: 4 fields is still legal) and `OamFrame.visible_pixels`/`behind_bg`/`hidden_pixels` return `None`, never `0`. `OamStream.has_visibility` says which kind of dump the reader holds; `measure_capture_overdraw.py` indexes its entry fields. ADR-0169's live viewer wire is **not** changed and `make capture-tool` needs no rebuild. The dump format is documented here, not in `docs/specs/`, so no spec semver moves.

## Context

**OAM (ADR-0222).** ADR-0197 §2 promised lint runs every hand-authored `<condition>` over the recorded routes and reports a verdict, stating a limit rather than hiding it. Five condition types still reported `not evaluable`, all blocked by what the OAM dump spells. `parse_grid_dump` resolves a cell to `(tileData, palette)` from the file alone, which makes `tileAtPosition`, `tileNearby`, `frameRange` and `memoryCheckConstant` evaluable; the sprite and position types stayed `not evaluable: OAM stream carries no tile data`. The dump is written in the save path next to `BuildSpriteVocabulary`; the poses come from the same `_oamFrames` (ADR-0179/ADR-0174). Option B would have written `entry.Shape` instead of `vocab.Find(key)`, leaving the color half unresolved; the interned palette id is what can make the color half resolvable from one file. `memoryCheck` needed no format decision — F12.6b retained the whole `$0000`–`$07FF` window ("a few lines away"). Non-goals: not what the recorder retains (`SameEntries` → `RepeatCount`, the 128-entries-per-frame bound); not a pack file ("Two env-gated save-time dumps"); not the loader (`HdPackConditions`); not `frameRange`'s phase problem (ADR-0189 §4). User's picks, verbatim: *"A: dump autodescritivo (Recommended)"* and *"So registrar (Recommended)"*. Met on the F12.6a Contra route: `nearThePlayer` = never held 0/749, `livesMatch` = mixed, the authored `nearThePlayer,spriteNearby,…` line going to `always held` / `mixed` / `never held` on the same 60 s route; shipped with `scripts/core_unit_tests.cpp` cases and `scripts/test_mep_conditions.py`. Option C was rejected: leaving the sprite and position conditions `not evaluable`, stated where the artist reads it (`ARTIST.md`, `docs/remastering-a-game.md`), would leave ADR-0189's most common condition — the one the recorder itself emits — the one lint cannot check. Logs: `docs/validation/slices/f12.6a-lint-authored-conditions-2026-09-19.md`, `docs/validation/slices/f12.6b-recorder-retains-internal-ram-2026-09-19.md`, `docs/validation/slices/f12.14-oam-dump-self-describing-2026-09-22.md`, `docs/validation/measurements/metroid-artist-workflow-evidence.md` (a hand author in `frameRange`, not sprite conditions). The PRD "Order" paragraph had said "an OAM-format decision nobody has taken".

**Mask (ADR-0234).** `Super Mario Bros. 3` builds its piranha-plant pipe with a mask sprite: an opaque 8×16 sprite behind the background, in front of the plant. The recorder reads OAM (ADR-0153 §2) and records it as an ordinary sprite; the pose clusters inherit it (`kPoseMaxGap`, `kPoseMinFrames`, `kPoseMinTiles`, ADR-0170; `OamFetchLatch` and `SpriteGrouping` take data and return data, ADR-0127). Measured on `runs/deep-smb3/run1` (2185 retained OAM frames, 3607 played): node 0 (`ShapeId` 147) and node 1 (148) each have 1619 appearances, 120 distinct `(x, y)`, a `y = 129` share of 1608 / 1619 (99.3 %), `screenFixed` (ADR-0173) **false**; 25 of 37 poses contain node 0 or 1 (92 of 316 tile slots). The issue's three criteria: behind-BG priority is dropped at the door (`OamFetchLatch::Decode` keeps only the two palette bits and two flip bits; the PPU knows `NesSpriteInfo::BackgroundPriority` but `HdBuilderPpu::DrawPixel` reads it only to set `transparencyRequired` on a background key, ADR-0159); "It only ever overlaps later-OAM sprites" holds (817 vs 1, 276 vs 0) but measures the symptom; `screenFixed` already declines it. The cause: the PPU's decision point is `NesPpu::GetPixelColor`, a sprite pixel drawn when `backgroundColor == 0 || !spriteTiles[i].BackgroundPriority`. Non-goals: not a general "which sprites did the player see" model — a sprite the 8-per-line limit or the sprite-mask bit hid reports no pixels and is not a mask; nothing is deleted (ADR-0173). Three implementations were falsified (node not appearance; per-appearance "no pixel shown" alone, which wrecked Punch-Out!!; frame not pose) and two review rounds followed (the tally counts the dot the PPU decided, not the shifter `_lastSprite` left set; the verdict is recorder-side). Cost, by diffing object files: `__text` **+36 bytes**; `DefaultNesPpu::GetPixelColor` 178 → 174, `HdNesPpu::GetPixelColor` 178 → 174, `HdBuilderPpu::GetPixelColor` 178 → 195; three recordings and a `headless_record ... screenshot` byte-identical. Evidence: `runs/505-analysis.md` (gitignored), `runs/0234/`, `runs/0234/verify_pose_drop.py`.

## Consequences

- **Every re-recorded pack changes.** SMB3 **37 → 28 poses, 316 → 177 tile slots** (mask claimed by 25 poses before, 2 after; 27 frames of 3607); Castlevania **258 → 258 poses, 3262 → 3262 slots**; Punch-Out!! **34 → 34 poses, 1350 → 1348 slots**; with the corrected tally Punch-Out!! goes **1348 → 1344** slots and **78 → 88** mask-labeled nodes; only 4 tiles actually leave a pose. `sheets/poses.json`, `adjacency.json` and the `-assets` figures of a re-record differ; a pre-ADR-0234 recording keeps its old text. Old dumps cannot be upgraded — the priority bit was never written.
- **Old readers.** ADR-0169's wire is untouched, so the formats differ by exactly `behindBg`/`visiblePixels`/`hiddenPixels`; a reader must not assume it parses with `parse_oam_dump`. Those three are evidence, not identity — de-duplication must keep ignoring them.
- **The exclusion is per pose.** A shape only sometimes hidden keeps its visible appearances (SMB3's 11 intro-card reuses of the mask's art, and the 12 where the mask peeks 2–4 px past the pipe). A mask tile leaving a pose must not take the pose, so the reduction re-applies #520's **cell** floor (`PoseCellCount`), not surviving tiles; measured on Bubble Bobble (**67 poses and 526 tracks before and after**, 227 → 223 tiles) and Contra (256 poses, 3063 tiles, 271 tracks). An appearance with no drawing facts is never a mask (`kEmptyCell`, `Node < 0`).
- **#504:** fused poses (`LabelPoseFusions`, ADR-0228) and this exclusion touch the same 13 poses; independent, land in either order, re-record after both.
- **The report changes shape.** `not evaluable` reasons citing "vocabulary indexes" are retired for the sprite and position types; `scripts/stages/README.md` must follow the writer; a script that still consumes the old dump (`scripts/mss_ram.py`-era spikes) breaks — the breakage is named in the slice, the logs are frozen. A recording without an `M` plane keeps `not evaluable: no memory stream in recording`.
- **Contradiction, unresolved.** ADR-0222's Status said ADR-0169's wire "was NOT changed" (its raw OAM attribute byte carries the palette implicitly), while its "Supersedes / amends" line called it an amendment "by reference (one palette byte per entry)"; the dump-format item below states the wire is not changed and `make capture-tool` needs no rebuild. Kept as written, not silently resolved.
