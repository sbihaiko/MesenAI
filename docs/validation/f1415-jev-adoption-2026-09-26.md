## 0. Why this document has two passes

**The first pass (2026-09-26, earlier the same day) is void.** Its verdict — 0
of 8 Jev runs, every one ending on the loop guard — was produced by a harness
with four defects, and its numbers are kept in §7 only as the record of what
those defects look like from the outside. The four, each fixed here with a test
that failed first (`runs/f1415-fix/red.txt`, 8 failures, then 0):

1. **The rewind ladder's floor.** `_checkpoint_at` clamped every rung to
   `max(start of the current screen, last real progress)`, and `_commit` marks
   the *newest* checkpoint whenever the watermark rises — so rungs 1, 2, 4, 8 and
   16 landed on one checkpoint. Measured on a ring of forty one-second
   checkpoints: `[40.0, 40.0, 40.0, 40.0, 40.0]`. The floor is now the start of
   the current screen and nothing else, and the same ring gives
   `[39.0, 38.0, 36.0, 32.0, 24.0]`.
2. **The loop guard's fingerprint.** It was computed from `played.state` — the
   result of an attempt, *rejected ones included* — so three macros that all fail
   from one spot ended near that spot and read as one loop: the fake reproduces
   the first pass exactly, `fingerprint (984, 859, 0, 16) seen 3x, 4x, 5x` and
   `reason: loop` after 5 decisions where the budget was 9. It is now the
   **committed head's** fingerprint (ADR-0238 §3, amended 2026-09-26): a rejected
   attempt moves nothing and is what `tried_here` records, and consecutive
   samples of one 8-px cell are one visit, because "the run is pinned" is the
   watermark detector's finding.
3. **Mega Man 3's progress field wrapped.** `$0025` and `$0027` are one byte
   each, so `ram-map.json`'s `abs_x` was not a route. The level's page is
   `$002D`; `abs_x` is now monotone (§3).
4. **The web-research worker never came back.** Two causes, neither of them the
   network: the module pinned `claude-deepseek-v4-flash[1m]`, which this CLI does
   not know (`[claude-code:unrecognized_model]` on stderr — it answers a trivial
   question, which is why it looked fine for two slices) and which on this
   module's own prompt returned **nothing at all** at a 150 s *and* a 240 s cap,
   where `sonnet` returned a usable proposal object in 34–63 s; and
   `--output-format json` writes a JSON **array of stream events**, not the
   `{"result": …}` envelope the module parsed, so a worker that answered
   perfectly was read as "answered no JSON object". Both are fixed (§6).

Nothing in the first pass's *design* was wrong: the arms, the states, the macro
library and the caps are the same, and the re-run below changes only what the
four defects forced.

## 3. The one data file this slice closed: Mega Man 3's level page

`scripts/stages/mm3/ram-map.json` steered by `$0027`, one byte, so its `abs_x`
read 59 / 152 / 145 / 56 at the route's four states where the route rises. The
page counter is **`$002D`** (byte-for-byte duplicated in `$00F9`), measured over
7 runs and 2 164 one-frame rows in one long-lived `step_emu` session
(`runs/f1415-fix/mm3/wrap_table.py`, evidence in `wrap-evidence.txt`): of all
2 048 addresses it is one of only two that move at every wrap and at no other
frame, and it moves back across the same boundary walking left.

| state | `$002D` | `$0025` | `$0027` | `camera_x` | `abs_x` |
|---|---|---|---|---|---|
| page 1, the committed route's end | 0 | 187 | 59 | 187 | 315 |
| page 2 start | 1 | 24 | 152 | 280 | 408 |
| page 3 start | 2 | 17 | 145 | 529 | 657 |
| the page-3 stall F14.15 measures | 2 | 184 | 56 | 696 | **824** |

`camera_x = level_page * 256 + camera_scroll_x` and
`abs_x = camera_x + ((player_x_low - camera_scroll_x) % 256)` — the modulo is
what makes the player's column a column while both bytes wrap. The map's
`progress` is now `abs_x` and its `screen` is `camera_x`, so a run needs no
`--progress-field` for this game, and `open.level_x_high_byte` is closed
(`open.stage_id` is **not**: `$05A0` and `$05E0` were both ruled out by
measurement — 95 and 457 moves in 901 rows, and a stage id is constant inside a
stage — and minting a second stage with equal frames needs a mint script that
does not exist in the tree).

The tips file's `abs_x` bands (140–1023, six bands over four pages of 256) were
written for exactly this scale, and every one of the route's four measured states
now falls in a band of its own, in order: 315 → `petit-snakey-stairs`, 408 →
`bubukan-pole`, 657 → `long-pit`, 824 → **`cloud-platforms`**. The first pass's
"no Mega Man 3 tip fires" was an artefact of the wrapping byte:
`scripts/test_mm3_stage_data.py` now pins the arithmetic and the four bands.

slice. See open problem 2.

**Adjacent finding — the cheat does not move the wall, again.** `C-mm3-cov` ran
from the same state under `cheat=00A2:9C` (ADR-0184 §3 rank 2, verified by
effect) and reached the same abs_x 906 in the same 208 frames as the uncheated
`B-mm3-tips-1`. A cheat does not remove a position stall (ADR-0238 §4), now
measured on a stall that *is* passed: the code changes who survives the corridor,
not where the corridor is.

## 8. Verdict and the reasons

**Do not adopt Jev beyond the spike.** One of §5's two clauses is met, and the
one that is not is the one about the product:

1. **It passes a stall the search cannot — clause 1, met for the first time.**
   Mega Man 3's page-3 wall: 5 of 5 arms, tips on and off, at 3.57–3.62× real
   time, deterministic repeats. The control (§5) passes on the first rung as it
   always did.
2. **The kit gains nothing — clause 2, not met.** A stall the search could not
   pass bought the recorded kit 0 keys the committed routes do not already
   record. The route reaches new level and paints no new tile-palette pair,
   because this game's bootstrap exports every CHR bank index. Until a *cell*
   or a *region* metric exists that this game does not saturate, "Jev passed"
   cannot be turned into a reason to ship a pack.
3. **One stall it still fails, and the reason is the state, not the model.** Stall
   A is one hit from death at the wall with no legal candidate for the base
   search; the ladder has a one-checkpoint ring, so eight questions are asked
   from one state. Jev got eight macros and four research proposals at it and
   moved abs_x by nothing. This is what an attempt cap looks like when the game
   has already decided.
4. **The speed target holds for the search and for a Jev pass, and not for a run
   that reaches research.** 3.57–4.26× for every arm in §2, §4 and §5 — against
   the ADR's ≥ 3× — and 0.18–0.32× for the four Ninja Gaiden arms, whose wall
   clock is one US$ 0.27 research pass.
5. **The budget clauses need rewriting before another slice.** See 3 below.

## 9. Open problems

1. **`abs_x` is now the monotone level x, and F14.13's route was pinned to the
   old one.** `scripts/route_search.py` and `scripts/test_step_emu_rom.py` use
   Ninja Gaiden's own `abs_x` (camera + screen x), untouched here, but a future
   Mega Man 3 search has to be re-measured against the new field — its stall
   frames and its goal numbers are in the old scale.
2. **The Jev route for stall B is verified and not committed — one generator
   short.** Everything about the route is now measured and reproducible *given
   the state*: it replays twice at three cuts with 0 bytes differing, it reaches
   abs_x 906 uncheated, and the state itself is reachable from versioned scripts
   (`mint-boss.txt` → `boss-run-slide.txt` → three `--no-jev` page runs and two
   crossings). What is missing is the piece that turns that into
   `page3-run.mss` the way `scripts/stages/` requires: a mint or a chain the
   library job can produce, carrying each run's idle tail (see §5). Writing that
   generator is the follow-up, and until it exists `library_job.start_plan`
   correctly refuses the route — a route whose state nothing produces is not an
   artifact, and shipping it would put an unrecordable row in every MM3
   recording report.
3. **The US$ 1.00 slice cap was spent by three research passes.** The Jev side of
   this slice is **US$ 0.001998** against its US$ 1.00 cap; the *workers'* own
   accounting is US$ 1.0581 — the cap was exceeded by 5.8% by the four Ninja
   Gaiden arms, each of which paid ~US$ 0.27 for one live pass that the 0.25
   per-arm budget could not absorb. The cap was set before a live pass's cost had
   ever been measured (the first pass's workers never answered, so they cost
   nothing). A research pass needs its own budget line, or the harness needs
   `--research-budget` separate from `--budget`.
4. **`--allowedTools` is not enforced by this CLI.** The worker's own init event
   lists every tool (`Task`, `Bash`, `Edit`, …) and a non-allow-listed tool
   executed in the probes (`runs/diag/`), so ADR-0238 §3's "a `claude -p` worker
   with web search and no other tool" is the argv's intent and not a guarantee.
   The prompt still carries no ROM bytes, no pixels and no key — the query is
   built from the game's name and a position — but the *tool* restriction is not
   what the ADR assumes.
5. **The tips file still has no gate for "the search is stuck".** All six Mega
   Man 3 tips are per-arena bands and now fire (§3), which is a real improvement;
   Ninja Gaiden's stall A is off every band it has, and a band is still not what
   a stall is about.
6. **`--no-jev` bounds a stall but does not search one** (first pass, unchanged).
