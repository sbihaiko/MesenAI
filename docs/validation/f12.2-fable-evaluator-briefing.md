# F12.2 — Fable evaluator briefing (no answer key)

This is the **only** document a Fable evaluator of F12.2 is given besides
the three artist guides, the emulator binary / tools, the two work copies
and the two ROMs. It is not the dispatcher script. If you have also been
handed `f12.2-copy-sheet-cell-panel-script.md`, this ADR, the PRD, or any
`scripts/*.py` source, **stop and say so** — the run is invalid.

Fill a dated log — `docs/validation/f12.2-fable-panel-<game>-<YYYY-MM-DD>.md`
— in the shape the Zelda C.5 log uses: Binary and inputs, the verbatim
step log with clock times, the results table below, then Defects. Repeat
for both games. Start the clock at the first launch and stop it when the
repainted shape is on screen, or when you give up.

## Who you are

You are a NES pixel artist. You have shipped two HD packs by hand-editing
`hires.txt` with a spreadsheet beside you, and you are trying this emulator
for the first time. You may read `docs/remastering-a-game.md` and the other
two guides that ship with the binary. You may **not** open any
`textures/hires.txt` at any point — that is a fail, logged with the clock
time and the question it answered. You may **not** read tool source.

## Goal

Within twenty minutes per game, from a paused frame of
`The Legend of Zelda (1987) (Nintendo).nes` and then of
`Contra (1988) (Konami).nes`:

1. Pick one background shape you can see on that frame and want to
   recoulour (a bush, a rock, a ground or wall tile — not a sprite).
2. Get that tile's identity out of the running emulator in a form you can
   paste into a sheet sidecar, **without typing hex from a spreadsheet**.
3. Paste it as a new cell on the work copy's `textures/sheets/misc.json`
   (`~/f12.2-panel/zelda/` and `~/f12.2-panel/contra/`). Grow
   `misc.png` / `misc.orig.png` only if the sheet has no free slot; paint a
   32×32 solid magenta square at the new cell's top-left; leave
   `*.orig.png` unpainted except for a resize.
4. `python3 scripts/mep_build.py build` on that work copy must exit 0 with
   no `error:` lines. `python3 scripts/mep_lint.py` on it must exit 0.
5. Copy the work copy to `<rom dir>/mep/` and reopen the same ROM. The
   shape you picked is magenta. Then stop the clock.

Work copies, not the live `auto/` packs. `mep/` next to the ROM is yours
to overwrite; do not hunt through `EnhancementPacks/`.

## The menu you would have seen

This machine cannot open the debugger viewer's right-click flyout from an
agent session. Setup therefore dumps the **visible, enabled** entries of
the Tilemap Viewer's context menu at a selected background tile, as the
viewer itself labels them. The dump is a text file in this sandbox named
`tilemap-menu-labels.txt` (one label per line). Treat that list as what a
right-click on the tile you picked would have shown. Name the line you
would click. Naming the HD-pack-format copy is a fail of findability, not
a shortcut.

If `tilemap-menu-labels.txt` is missing, that is a dispatcher defect: stop,
do not guess.

After you name the line, the dispatcher pastes whatever that action copied
into a scratch file you can read. That paste is the only evidence the
click worked — there is no toast.

## Log

One line per step with the clock time: what you ran, what you saw, every
time you had to stop and look for an answer a guide did not give (say
where you looked). If you feel you must open `hires.txt` or tool source,
log it as a stop and then do it — the run will fail criterion 4, and the
stop is still the finding.

At the end, five lines:

1. Elapsed, per game.
2. Number of stops, and what they were.
3. Whether the magenta shape appeared, on the supported path, with no
   `hires.txt` edit.
4. Whether you opened `hires.txt` (yes is a fail).
5. In one sentence, whether picking a key this way beats typing it from a
   spreadsheet. This sentence is an observation, not a pass.
