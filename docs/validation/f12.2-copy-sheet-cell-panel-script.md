# F12.2 — *Copy as MEP sheet cell* human panel script (unfilled)

This is the script an evaluator executes, not a completed log. The Phase 12
acceptance bullet requires that a slice changing what the artist sees is not
shipped until **a person who did not build it** logs the cold-read rows; the
F12.2 row names one specifically: *"a person pastes one cell and paints it
without reading `hires.txt`."*

Fill a dated copy of this file — `f12.2-copy-sheet-cell-panel-<YYYY-MM-DD>.md`
— in the shape `f918v-current-binary-painting-2026-09-15.md` uses: a **Binary
and inputs** header, the evaluator's verbatim log with clock times, the results
table, then **Defects filed**.

## Rules for the evaluator

- You did not build this. You may read `docs/remastering-a-game.md`. You may
  **not** open `textures/hires.txt` at any point — that is criterion 4, and
  opening it is a fail, logged with the clock time and the question it
  answered.
- Start the clock at P1 and stop it at P14. Record the time of every step.
- Repeat the whole run for both games.

## Setup — done before the evaluator sits down, not on their clock

Two things will silently defeat the run if skipped. Both were found while
drafting this script, not during a panel.

**S1 — the packs must be re-recorded first.** The `auto/` packs currently
installed beside both ROMs do **not** rebuild: `mep_build.py build` exits **2**
with 13 errors on Zelda (`spr004`, `spr005`, `spr007`, …) and 24 on Contra,
each reading *"crop(s) carry a flip-baked tile key the run time never looks up
… re-record the pack with a build that has ADR-0178"*. Both recordings predate
ADR-0178. Re-record both games with the current binary and confirm
`python3 scripts/mep_build.py build <pack>` exits 0 on each **before** the
panel starts, or the evaluator hits a hard refusal at P13 with no way forward.
This is not a defect: ADR-0178 changed the contract and the refusal is the
correct behaviour — re-recording is what the error message asks for, and the
user's decision (2026-09-17) is to re-record rather than relax the gate.

**S2 — give the evaluator work copies, not the live packs.**

- `~/f12.2-panel/zelda/` ← `<roms>/The Legend of Zelda (1987) (Nintendo)/auto`
- `~/f12.2-panel/contra/` ← `<roms>/Contra (1988) (Konami)/auto`

**S3 — move the community pack aside.** Both game folders carry an
auto-installed `mep/` (Zelda `pack_id issue-139`), and `mep/` wins over `auto/`
entry by entry (ADR-0147). Painting in `auto/` and reopening the ROM would
render the community art instead, with nothing on any surface saying so — the
exact failure shape C.5 hit. Rename `<rom dir>/mep` to `<rom dir>/mep.off` in
both folders and set `AutoInstallCommunityPacks` to `false` in Preferences.

## Run

P1. Launch the emulator (`make ui`, or the released app). You see the Player
shell: a game list / welcome card, no menu bar.

P2. Press **Esc** for the thin overlay and click **Advanced GUI**. A classic
menu bar appears: `File  Game  Options  Tools  Debug  Help`.

P3. `File > Open` and load `The Legend of Zelda (1987) (Nintendo).nes` or
`Contra (1988) (Konami).nes`. The game boots and runs.

P4. Play to a screen showing a shape you want to repaint — a bush or rock on
Zelda's first overworld screen, a ground or wall tile on Contra's stage 1.
Press **Esc**. The picture freezes.

P5. `Debug > Tilemap Viewer` (**Ctrl+1**). A window opens showing the full
nametable as the paused frame draws it, with a tile grid over it.

P6. Hover the shape you picked. The right-hand panel shows that tile's
address, palette index and a magnified preview. Confirm the preview is the
shape you meant.

P7. **Right-click that tile.** The menu ends with a separator and two entries:

```
Copy tile (HD pack format)
Copy as MEP sheet cell
```

Click **Copy as MEP sheet cell**. *Nothing visible happens* — no toast, no
status line, no highlight. The clipboard is the only evidence.

P8. Paste into a scratch text file to see what you got. It must be one line of
this shape (real keys from the shipped unit tests):

```
{"tile": "384CC6C6C66438000000000000000000", "palette": "0F300012"}
```

Both bounded games are CHR RAM, so there is no `"index"` field; on a CHR ROM
game the same action emits a third field, `"index": 2`.

P9. Open `~/f12.2-panel/<game>/textures/sheets/misc.json` in a plain text
editor. You see `"columns"`, `"cell": {"w":16,"h":16}`, `"gutter": 1` and a
`"cells"` array. Scroll to the end of `"cells"`.

P10. Append one cell, pasting the clipboard text as the **first** entry of
`tiles` — the three `null`s are the cell's other three 8×8 quadrants, which
have no art. Mind the comma before the new object, and save.

```json
{"index": 23, "x": 52, "y": 69, "count": 1, "context": "misc", "tiles": [
  {"tile": "384CC6C6C66438000000000000000000", "palette": "0F300012"}, null, null, null]}
```

P11. Open `~/f12.2-panel/<game>/textures/sheets/misc.png` in your image editor.
The picture is a grid of 64×64 upscaled cells with a 4 px gutter, and the
bottom row has empty space.

P12. Fill a **32×32 px** square of solid magenta at the top-left corner of the
cell you just declared, and save the PNG. Do **not** touch `misc.orig.png` —
that twin is what tells the builder your cell was painted.

P13. Build:

```
python3 scripts/mep_build.py build ~/f12.2-panel/<game>
```

You see `info:` lines, no `error:`, and the command exits 0.

P14. Copy `~/f12.2-panel/<game>/` to `<rom dir>/mep/`, then `File > Open` the
same ROM again — there is no live reload, that is F12.3 and it is not shipped.
Play back to the same screen. **The shape you right-clicked in P7 is now a
magenta square.** Stop the clock.

P15. Write down: elapsed minutes, how many times you looked something up and
where, whether you ever opened `hires.txt`, and in one sentence whether picking
a key this way beats typing it from a spreadsheet.

## Why criterion 5 is written against `build`

The F12.2 row's stop rule reads *"Stop when the pasted text round-trips through
`mep_build.py --verify` on both."* There is no such flag. `scripts/mep_build.py`
accepts only `build`, `pack`, `rename-audio-id` and `check-coverage`; `verify`
is a subcommand of `scripts/mep_import.py`, where it checks a rebuilt imported
project against the legacy pack it came from — a different subject. The kit
generators' `--verify` is a third thing again (key conservation across kit
extraction).

What exists and does measure the round-trip is `mep_build.py build` itself: the
pasted key comes back out as a `<tile>` line pointing at the painted cell.
Verified on both bounded games while drafting this script:

- Zelda — `<tile>4,384CC6C6C66438000000000000000000,0F300012,208,276,1,N,0,0`,
  with `<img>sheets/misc.png` at index 4; `208,276` is exactly the painted crop.
- Contra — `<tile>2,003FFFFFFF7F84D10000000000807B2E,0F192908,140,276,1,N,0,2`,
  with `<img>sheets/misc.png` at index 2.

`check-coverage` does not fit: it proves nothing was *lost* against an earlier
baseline, and says nothing about a key that is newly *added*.

Criterion 5 is written against `build` on that basis, and the PRD row's stop
rule was reworded to match (user's decision, 2026-09-17): the round-trip is
`mep_build.py build` emitting the pasted key as a `<tile>` whose `x,y` is the
painted cell's crop, with `mep_lint.py` exiting 0. A machine-readable
`verify-cell` subcommand remains a possible follow-up slice, deliberately not
smuggled into this panel.

## Known traps in the shipped code

Found while drafting; each shapes a step above.

1. **No live reload.** "paints it" cannot be seen without closing and
   reopening the ROM. F12.3 is the slice that fixes this. Hence P14.
2. **The action gives no feedback at all.** On failure — a non-hex or
   wrong-length key, or a tile whose 16 bytes would run past the end of CHR —
   the code deliberately leaves the clipboard untouched, which is the same
   observable behaviour as success. The evaluator cannot tell *copied* from
   *refused* from *stale clipboard* without pasting. P8 exists only for this;
   criterion 8 records it.
3. **A 16 px-tall sprite copies two objects, not one.** With
   `isLargeSprite`, the bottom tile's object is appended on a second line with
   **no comma between them** — deliberate, and the code says why: the entry the
   paste lands next to decides whether a separator is needed, and an unasked-for
   comma is the one thing that breaks the sidecar's JSON. The PRD row says
   "pastes one cell", so this script routes the panel through the **Tilemap**
   Viewer. A Sprite Viewer pass on an 8×16 game is worth logging as a separate
   observation, never as criterion 3.
4. **Menu visibility is narrower than the row suggests.** The item is
   `IsVisible => CpuType == Nes` in all three viewers, and enabled only for
   `NesPpuMemory` / `NesChrRam` / `NesChrRom`. In the **Tile Viewer** the
   "Source" dropdown must be a CHR source or the item is greyed out. In the
   **Tilemap Viewer** `IsEnabled` checks only the memory type, not whether a
   tile is under the cursor — so the item can be clickable with nothing
   selected, and the click is a silent no-op leaving the previous clipboard in
   place. An evaluator can paste an earlier tile's key and never know. P8
   catches it.
