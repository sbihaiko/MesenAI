# F12.15 — a recorded screen does not hide a behind-background sprite over empty canvas (2026-09-22)

Scope and stop rule live in the PRD (Part A, row F12.15); the decision is
ADR-0224, accepted 2026-09-22. This log is the evidence for the Core half of
the slice — Decision 1 (the tag), 2 (the renderer) and 3 (the recorder writes
it) — measured on ADR-0221's Punch-Out!! route. Decision 4 (the overdraw
tool's split columns) is being built in parallel and is **not** in this log;
Decision 5 (spec, `remastering-a-game.md`, `ARTIST.md`) is not either.

## What shipped

- `Core/NES/HdPacks/HdBehindBgSpriteRule.h` (new, host-free per ADR-0127) —
  the tag literal `<bgPreservesBehindBgSprites>`, `IsTagLine` (the loader's
  exact-line match, no arguments), `KeepsBehindBgSprite` (the per-pixel
  predicate: opted in, `lowestBgSprite != 999`, `BgColorIndex == 0`, and a
  layer-2 background actually changed the pixel) and `WriteHeaderTail` (the
  `<options>` line when any flag is set, then the tag, unconditionally).
- `Core/NES/HdPacks/HdData.h` — `HdPackData::PreservesBehindBgSprites`, a
  dedicated bool. `HdPackOptions` and `HdPackOptionsToString` are untouched.
- `Core/NES/HdPacks/HdPackLoader.cpp` — the tag dispatches into that bool
  (no error path, so an unknown-tag emulator and this one skip the same
  lines); `MergeLowerLayer` ORs it across stacked packs like `OptionFlags`.
- `Core/NES/HdPacks/HdNesPack.{h,cpp}` — the behind-background sprite pass is
  now `DrawBehindBgSprites`, called where it always was and, when the
  predicate says so, **again after the layer-2 pass** — ADR-0224 §2's
  "equivalently" form. Layers 0/1/3, the tile draw, front sprites and the
  issue-#328 suppression counters are not touched; without the tag the
  predicate is constant-false.
- `Core/NES/HdPacks/HdPackBuilder.cpp` — `SaveHdPack` calls `WriteHeaderTail`
  instead of writing `<options>` inline, so every recorded pack (bootstrap
  `auto/` included) carries the tag right after `<options>`. Net **-1 line**
  (2427 -> 2426 against the ADR-0137 ceiling of 2428, not raised).
- `Core/Core.vcxproj`, `Core/Core.vcxproj.filters` — the new header registered.
- `scripts/mep_lint.py` — `bgPreservesBehindBgSprites` added to `NES_TAGS`,
  so the linter accepts it and says nothing about its absence (ADR-0224 §3).
- `scripts/core_unit_tests.cpp` — BlocoP4, 16 checks: the predicate is false
  for every input when the pack is opted out; kept over colour 0; hidden under
  an opaque background pixel (`BgColorIndex != 0`); no re-apply when no opaque
  behind-background sprite drew (999) or when layer 2 did not paint; front
  sprites unaffected; the loader's line match rejects arguments and the
  `<options>` spelling; the writer emits `<options>automaticFallbackTiles\n<bgPreservesBehindBgSprites>\n`
  for CHR ROM and only the tag for CHR RAM; `HdPackOptionsToString` gained no
  token. The pixel cases run GetPixels' pass sequence as a **model** over flat
  colours with the real predicate deciding — `HdNesPack` needs `NesConsole`
  and is not in the unit-test link set. The renderer itself is proven below,
  on the headless render. `make core-unit-tests`: **982/982 after the rebase onto main with ADR-0209 Q1's cases; 953/953 on the pre-rebase base** (937 before).

`make doc-checks`: rc 0 (`OK: Core/NES/HdPacks/HdPackBuilder.cpp has 2426
lines (max 2428)`).

## The recording

ADR-0221's route — 60 s from power-on, `bootstrap`, no input, ROM copied to a
scratch directory so no sibling pack is discovered; grid dump and OAM stream
dump on (ADR-0222 self-describing format):

```
MESEN_SHEET_GRID_DUMP=<d>/grid.txt MESEN_OAM_STREAM_DUMP=<d>/oam.txt \
  <new headless_record> <d>/po.nes 60 <d>/run bootstrap log
```

The pack lands at `<d>/po/auto/textures/hires.txt`; line 803 is
`<options>automaticFallbackTiles`, line 804 is `<bgPreservesBehindBgSprites>`
— the recorder wrote the tag. 10 `<background>` lines, byte-identical to the
F12.13 pack's, with identical `tileAtPosition` gates. The recording is
**route-matched but not byte-identical** to F12.13's: 3 351 played / 592
retained frames in both grid dumps, `F`/`M` lines identical in count, but
the shape/palette intern order differs from line 3 (`P 2` vs `P 0`) and the
sprite-sheet `spriteNearby` conditions are renumbered (`spr007`.. shifted by
one sheet; 692 vs 672 condition lines, 11 646 vs 11 606 `<tile>` lines). The
capture side — the 10 screens and their gates — is what this slice measures,
and it is identical; the sheet-side drift was not traced here.

Two packs were then made from it: **tag** (as recorded) and **notag** (the
same directory with the one tag line deleted; `grep -c` 1 / 0).

## Cost

Whole-run wall clock of `headless_record` (emulation + render + PNG; the
harness reports no render-only figure), summed over the 36 runs, 59 532
frames:

| configuration | sum wall | ms / frame |
|---|---|---|
| new dylib, tag | 156.7 s | 2.632 |
| new dylib, no tag | 157.1 s | 2.639 |
| old dylib, no tag | 149.5 s | 2.511 |

Tag vs no tag on the same binary: **no measurable difference** (-0.3 %, inside
the per-run spread, e.g. 3.625 vs 2.417 ms at 11 s between two runs that render
the same frames). The new binary is ~5 % slower than the old on the tag-less
pack; that is two different builds measured on a shared machine while other
jobs ran, and the byte-identical output says the pixel work is the same — it
was not separated from build/thermal noise here. Per-frame figures for all 36
timestamps are in the scratchpad's `analysis.txt`.

## What this log does not deliver

- **Decision 4** (split `erased background` / `erased sprite` columns) — not
  here; the table above carries `pending` where they go. The stop condition
  ADR-0224 states "on the split columns, never on the total" is therefore
  read here off the total plus ADR-0223's hand trace, not off the tool.
- **Decision 5** (hires.txt extension draft, `remastering-a-game.md`,
  `ARTIST.md`) — not written.
- **The 30-ROM library** was not re-recorded or re-rendered: three ROMs,
  three timestamps each, tag-less packs, is the regression half only. The
  ADR's "measure on the 30-ROM library before and after" render-cost clause
  is answered on Punch-Out!! alone, whole-run wall clock, not render-only.
- `HdNesPack::GetPixels` has no direct unit test — the BlocoP4 pixel cases are
  a model of its pass order around the real predicate. The renderer's
  behaviour is established by the 36 + 9 byte-identical no-tag renders and the
  41–43 s zero, not by a unit test.
- A stacked human + `auto/` pack where only the lower layer carries the tag
  (`MergeLowerLayer` ORs it upward) was not exercised.
- Issue #339's first cause (the card, 19–27 s) is untouched: 437 -> 374 is the
  fight window only, as the ADR says it would be.

## Independent verification (Sonnet, same day)

Every number above reproduced from the artefacts: 36/36 and 9/9 byte-identical
without the tag, tag placement, the split totals (374 = 374 + 0; 437 = 374 +
63, 59 behind-bg). Verdict PASS with two caveats kept as stated:

- **Stop condition (2) is partially met.** The predicate, the tag parse, the
  writer and a model of the pass order have unit cases; `HdNesPack::GetPixels`
  itself has none, because `HdNesPack` needs `NesConsole` and is outside the
  `make core-unit-tests` link set (pre-existing). The tag-on renderer path is
  evidenced by the headless renders, not by a unit test.
- **Layer 3 (priority 30–39) is untested with the tag.** The re-applied
  behind-background sprite pixel can still be overpainted by a layer-3
  background, which runs unconditionally afterwards; ADR-0224 §2 does not
  discuss it and no pack in the sweep has one. Recorded as an open edge, not
  a defect.
