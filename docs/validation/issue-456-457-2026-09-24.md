# Issues #456 and #457: rebuilt sheet crops on Punch-Out!! (2026-09-24)

This log covers two bugs, found on Punch-Out!! (CHR ROM, MMC2). `mep_build.py
build` rebuilt a pack from its sheets, and that pack drew differently from the
recording (`auto/`):

- **#456**: background crops came back with an opaque backdrop, which hid
  behind-background sprites. Glass Joe disappeared behind the floor.
- **#457**: mirrored sprite cells stayed baked on an index-keyed pack, so the
  mirrored poses rendered torn.

The log records the root causes, the fixes, red-before-green excerpts,
mutation results and the end-to-end numbers. Raw material (the recording, kit,
round-trip packs, screenshots and scripts) lived in a session scratchpad and
is not versioned. Core is unchanged.

## Root causes

### #457: `cmd_build` skipped the un-bake on index-keyed packs

The recorder bakes a sprite's OAM flips into the shape it records. The run
time mirrors the replacement art itself, so ADR-0178 (#255) has the build
un-bake each mirrored crop (and its `*.orig.png` twin, #329) and drop
`source`/`mirror` from the sidecar.

In `scripts/mep_build.py` `cmd_build`, the per-crop loop tested `if
index_keyed:` first. Only then did it test `elif unflipped is not None:`,
the branch that queues the un-bake. So on a CHR ROM game (ADR-0172 index
keys) no mirrored cell was ever un-baked. The run time then flipped a
bitmap that was already flipped.

### #456: the sheet shows colour 0 opaque, the recording does not

The recording keeps colour 0 transparent on every background key that a
behind-background sprite was drawn over:

- `HdBuilderPpu::DrawPixel` sets `hasBgSprite`, and that sets
  `TransparencyRequired`.
- `HdPackTileInfo::ToRgb` then keeps colour 0 transparent.

That transparency is what lets the sprite show through, as on hardware.
`SheetRender::RenderTile` deliberately draws a background cell with colour 0
opaque (`transparentIndex0 = false`), so that an artist painting a tree does
not paint over holes. `mep_build` points `hires.txt` at the sheet pixels as
they are, so every such key lost its transparency. On the Punch-Out!!
recording, 205 keys were transparent in `auto/` and opaque in the rebuild.

### Second cause checked for #457: a separate recorder bug

The torn poses also have a separate cause in the recorder, `HdPackBuilder::ShapeIdFor`.
It interns shapes by `HdTileKey`, which on a CHR ROM game compares
`TileIndex` only. A tile index drawn both flipped and unflipped collapses into
one shape. That shape keeps the first sighting's baked art and `Mirrors`, and
`OamEntry` has no flip bit.

On the recording (the shadow OAM at `$0200`, 2 019 frames), 58 of 183 OAM tile
bytes are drawn both ways. The sidecars, however, give 0 of 418 sprite indexes
more than one orientation. So kit figures and poses can show a pose in the
wrong orientation (pose005, pose023). This is not a build defect, and it is
not fixed here (draft below).

## Fix

- **#457.** The loop now tests `if index_keyed or unflipped is not None:`. It
  keys by the index on an index-keyed pack, and by the unflipped data
  otherwise. In both cases it queues the un-bake whenever the entry carries
  `source` + `mirror` (and is not a fold).
- **#456.** The new `scripts/sheet_pixel_fixes.py` holds the sheet pixel
  corrections. The existing `flip_region` and `sidecar_drop_mirrors` moved
  there from `mep_build.py`. It adds three pieces:
  - `KeySourceAlpha` reads, from the key source's own `<img>`/`<tile>` crops
    at its own `<scale>`, which keys are drawn with a transparent pixel.
  - `see_through_places` returns the background crops to clear: every crop
    of such a key, closed to a fixed point over crops that keys share (an
    alias, or one drawing under two CHR indexes). Sprite sheets and `FF…`
    palettes are not background crops.
  - `punch_backdrop` clears a crop's colour-0 positions wherever the sheet
    pixel still equals the twin's backdrop pixel. It clears the twin in
    lockstep, so the artist's own paint stays and the cell still reads as
    unpainted. A twin pixel that is already transparent is skipped, which is
    what makes a second build a no-op.
- Punching runs after the un-bake, at the colour-0 positions of the
  **unflipped** tile.
- `mep_build.py` goes from 2 068 to 2 024 lines (ADR-0137 ceiling 2 070).
- `sheet_pixel_fixes.py` is listed in `scripts/tools-zip-manifest.txt`.

No accepted ADR is contradicted. ADR-0178 already requires the un-bake. ADR-0224's
`<bgPreservesBehindBgSprites>` covers `<background>` captures only, not
`<tile>` crops.

## End to end: Punch-Out!!

- **Recording.** Made with this branch's binary. The kit's sprites verify
  finds 1 653 keys after a control rebuild and 1 653 in the kit: 0 lost,
  0 invented.
- **Round trip.** It follows the kit recipe (#435 order), with no
  workaround: build, import figures, build, lint, build. Each step was run
  in two arms:
  - control: unpainted;
  - painted: one pose011 cell painted magenta, 1 024 px.

  Every step exits 0. In both arms, the third build is byte-identical to the
  second. The painted `hires.txt` is byte-identical to the control's.
- **Background crops cleared.** unsorted 343, metatiles 47, obj000 8,
  usr014 10, misc 1.
- **Rule orientation.** Control and painted each have 561 as-ROM,
  196 symmetric, 9 other and **0 mirrored**. Before the fix there were
  70 mirrored.
- **Alpha vs `auto/`.** 406 keys are transparent in both and 734 are opaque
  in both. **0** keys are transparent in `auto/` and opaque in the rebuild
  (before the fix: 205). 16 keys are opaque in `auto/` and transparent in the
  rebuild: those are the shared crops the closure clears.
- **In game at 4.6 s.** `auto/` shows 0 magenta px, control 0, and painted
  **1 024 px**, bbox (540,380)–(571,411). Glass Joe is whole in both arms.
  Inside Joe's box, `auto/` and control differ in 8 772 of 190 400 px: nearest
  vs xBRZ upscaling (#447).
- **In game at 1.2 s.** This is the H-flipped pose that was torn before the
  fix. Joe is coherent in control and in painted.

## Found along the way (drafts, not filed)

1. **The recorder collapses a CHR ROM tile drawn both flipped and unflipped
   into one shape** (`HdPackBuilder::ShapeIdFor`, `HdTileKey` equality on
   `TileIndex`). Details are under "Second cause checked for #457" above. The
   shape keeps the first sighting's baked art and mirror, so kit figures and
   poses show some poses in the wrong orientation.
2. **`mep_figure.py import` writes paint on a mirrored cell in the baked
   orientation, into a crop the build has already un-baked.**
   - Repro: in the usr004 figure, paint the left half of pose030's mirror-H
     cell (key `1E01`/`FF352708`). The owner crop, usr012.png at (76,436),
     gets magenta in left 272 / right 0 px, so the paint shows mirrored in
     game.
   - Scope: CHR RAM packs too, since #255.
   - The painted cell of the round trip above is not mirrored, so that run
     is not affected.
