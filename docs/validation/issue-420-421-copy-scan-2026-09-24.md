# #420 / #421 — the F12.2/F14.2 copy scan: which pack it checks, which nametables it walks

**Date:** 2026-09-24
**Base:** `main` @ `9a0ff899`, one worktree, clean core build.
`InteropDLL/obj.osx-arm64/MesenCore.dylib` sha256
`7f6fbc3ed3616b1947c66c8377c8f27f5d76e412d5389f3e890bd6ac879dd2db`,
`scripts/headless_record` sha256
`127746c6e0aabf9d80d8528e38d989e25e9426dcec40d460bdc4d424f18fea91`. No Core
file changes, so the same library backs the "before" and "after" runs.
**Found by:** `docs/validation/f14.2-cold-read-rescore-2026-09-24.md`, causes
B and C, bug entries 2 and 3.

## Root causes

**#420 (cause B).** The copy checks each tile's palette against the pack the
core has loaded (`NesPackTilePalette`, #342). `f122_prepare_evaluator.py`'s
`scan()` ran `make headless-ui-tests` with the ROM's sibling folder holding
only the recording's bootstrap `auto/`. So the loaded pack was `auto/`. On
Zelda II it carries 8 192 `defaultTile=Y` rules, and each one answers the
palette check with the wildcard. Every live palette therefore passed, both on
tiles the baseline pack keys under another palette (Zelda II 28,0) and on
stale keys that have no baseline rule at all (Tetris 2, The Flintstones).

**#421 (cause C).** `WalkTilemap` in `CopyAsMepSheetCellTests.cs` walked
`x < 256, y < 240`. That is nametable `$2000` of the Tilemap Viewer's 512x480
"Nametables" picture. Cells the frame drew from nametables 1–3 were never
asked for.

## Fixes

- **#420, `scripts/f122_prepare_evaluator.py` `scan(rom, pack, state, table)`.**
  For the duration of the scan:
  - the baseline pack (the one the evaluator's work copy is made from) is
    installed as `mep/`;
  - `auto/`, and any `mep/` already there, are parked as `*.scan-aside`;
  - both are restored in a `finally`.
  With `auto/` gone, the core can start a bootstrap recorder on ROM load
  (measured on Super Mario Bros.: `auto/audio/.recorder`). So the restore
  drops whatever the scan's own run wrote into the slot before it renames the
  real `auto/` back.
- **#421, `UI.HeadlessTests/CopyAsMepSheetCellTests.cs` `WalkPositions`.** The
  walk covers every tile of the picture the viewer shows
  (`ViewerBitmap.PixelSize` in `GridSizeX/Y` steps). The copy itself decides
  what was drawn: ADR-0215's inversion refuses a cell no visible scanline
  fetched (`NotDrawnThisFrame`), including the mirror tab of a mirrored
  nametable. So the table holds the frame's cells from whichever nametable
  drew them. Its coordinates are the viewer's: columns 0–63, rows 0–59.
- **Follow-on in the dispatcher.** `dump_coverage` caps its share at 1.0,
  because a scanline fetches a 33rd column for fine X and a full table names
  990–1 023 cells. The `index/<game>.md` and log wording no longer says "the
  dump is one nametable".

No ADR was needed: ADR-0215 already defines "drawn". ADR-0214's protocol is
unchanged, and so is what is handed to the evaluator; only its content is
now correct.

### #421 — `The_scan_offers_a_line_for_every_cell_the_frame_drew_from_any_nametable`

native core and `MESEN_NES_ROMS`, and skips in CI. It copies Zelda II to a
pack-free temp folder and emulates 2 s from power-on with no state, so the
trace is fresh. It derives the drawn cells from `GetNesScanlineTrace`

## E2E: the scan per game

Inputs:

- the F14.2 states (`~/f14.2-opus-sandbox/frames/<game>.mss`, sha256 prefixes
  below);
- the library ROM bytes;
- the recording's `auto/` and baseline pack from `runs/f12.2-sweep`. F14.2's
  own baseline packs were not kept, so "keys without a baseline rule" is
  measured against the 2026-09-19 baseline of the same game.

Each configuration is the real `The_dispatcher_can_read_every_tile_of_a_paused_frame_as_a_cell`
run through `dotnet test --filter`. "after" goes through the real

### Reading the table

- **#420 is closed on its repro.** Zelda II's 28,0 copies as `0F2B0F00`, the
  baseline's only palette for index 376. Every "after" table holds 0 keys
  without a baseline rule. The two stale keys F14.2 named are gone.
- **#421 is closed on its repro.** Zelda II and Gauntlet now carry the
  nametable 2 cells the frame drew. Super Mario Bros. carries nametable 1.
  "Lines" reaches 990–1 023, a whole screen, wherever the trace is fresh.
- **The four blank-tile games only improve once #419 lands.** With the stale
  trace ("after"), Bubble Bobble, Contra and Pac-Man walk every drawn cell,
  and every one is still blank. Punch-Out!! drops to 11, because the stale
  boot frame's keys have no baseline rule and are now refused. With the #419
  stand-in they offer 74 to 342 non-blank cells, where F14.2 offered none.
- **"after" without #419 is sometimes smaller than "before"** (Tetris 2 61,
  The Flintstones 625 with 10 non-blank). This is not a regression. Those
  tables used to be the stale boot frame's keys, waved through by `auto/`'s
  wildcards. #420 now refuses them, and #419 is what puts the right ones
  back.

## Limits

- The full `f122_prepare_evaluator.py` (probe, mint, render, tilemap) was not
  re-run. The E2E drives `scan()` itself against the F14.2 states, because
  F14.2's recorded packs are gone and re-minting would change the frames
  being compared.
- `visible_window` still votes in one space. A window that wraps from the
  right-hand nametables back to column 0 splits its votes and may go
  unmeasured. The picture is then handed over without the cyan box, as
  before.
- The four-nametable tilemap picture is up to 64x60 cells (about
  3 073x2 881 px at scale 6). Nametables the frame did not draw stay empty.
