# F12.7 — a legacy plain HD pack imports and rebuilds pixel for pixel (2026-09-19)

The PRD row's stop rule: `mep_build.py build` on the imported project equals
the input by `(tileData, palette, condition)` **and** by pixels (ADR-0198 §1).
The 2026-09-17 run
([log](f12-7-legacy-pack-import-2026-09-17.md)) met the rule-set half
everywhere and the pixel half on two packs only; on a pack that keys one
pattern at several crops it missed by 914 keys (Contra80s, 10.2 %) and 1 467
(Super Mario Bros., 40.7 %), and said so. This run closes that half and
re-measures the three packs that are on this machine.

Result, in one line: **0 keys differ on all three packs**, and `verify
--strict` passes on Ninja Gaiden and on Contra80s' and SMB's split patterns.

## 1. What changed

The 2026-09-17 log named two ways to close the gap and took neither, because
both were decisions. The first of them — F12.6a, ADR-0197 §1, "a sheet cell may
carry its own condition" — shipped on 2026-09-19, so this slice is built on it.

- **`scripts/mep_conditions.py`** now holds the whole variant model, in one
  place: `inherited_variants` (moved verbatim from `mep_build`), `cell_condition`,
  `rest_for` and `variants_for`. A crop can say which rules it carries in three
  ways, and only the third is new:
  1. *inherit* — the cell says nothing and the key source decides. Every
     recorded pack, unchanged.
  2. *authored* — ADR-0197 §1's `condition` field: `[name]` plus the ADR-0189
     §3 bare twin (#256). Unchanged.
  3. *exact* — `"exactCondition": true`: the crop emits exactly one rule,
     `[name]`, or the bare unconditional rule when `condition` is absent. No
     inherited sibling, no synthesised twin.
- **`scripts/mep_build.py`** reads that model instead of computing it (net −20
  lines; the ceiling of 1945 was not touched, and did not need to be). One
  behaviour change beyond the new mode: an authored cell's trailing `<tile>`
  fields are now taken from the key source's own rule for that condition
  (`rest_for`) instead of the hardcoded `1,N`. 576 of Contra80s' 592 split
  patterns give a different brightness to different conditions, so the
  hardcoded default would have been a silent rewrite.
- **`scripts/mep_import.py`**'s `_plan_cells` splits a pattern that the
  manifest draws at more than one crop into one *exact* cell per rule, at that
  rule's own crop, naming the condition the rule carried. The sidecar **cites**
  the pack's own `<condition>`, which the key source already defines, and never
  writes a `conditions` block of its own: the import authors nothing.
  Patterns drawn at a single crop keep the old path exactly (one cell, aliases,
  conditions inherited from the key source), so nothing about Ninja Gaiden's
  output moved.

Because each rule of a split pattern now has one cell and one only, **no key is
emitted twice**, and no precedence rule (painted-beats-untouched, sheet rank,
emission order) decides which crop an imported key draws from. That is why the
fix does not depend on the `*.orig.png` twin being lossless at `<scale>2`.

## 3. How "equal" is measured

`verify` is ADR-0198 §1's acceptance test, unchanged by this slice:

- **rule set** — every rule of both manifests is mapped to its loader key,
  `("data"|"index", tileData, palette, condition)`, reading the tileData field
  the way `HdPackLoader::ReadTileData` does at each manifest's own `<ver>`
  (decimal below 103, hex at 103+), and the two key **sets** are compared.
  Rule order may differ; nothing else may.
- **pixels** — for every shared key, the `8*scale` block the built manifest
  names is hashed (sha256 over RGBA bytes) and compared against the block the
  input's **first** matching rule names, which is the one `GetMatchingTile`
  draws. A key whose built rule points at any other art counts as *differs*.
  The comparison is over content, never over coordinates: the import relays the
  crops on a fresh 16-column grid on purpose.
- **carried lines** — `<condition>`, `<background>`, `<addition>`,
  `<fallback>`, `<bgm>`/`<sfx>` and the stray non-tag lines, compared as sets
  across both manifests (build hoists definitions above the first rule that
  cites them).
- `--strict` additionally fails on the ADR-0189 §3 bare twins build adds to a
  conditioned key the input left without one.

## 8. Honest limits

- **Bomberman was not re-measured.** It is not installed and not cached, and
  this run did not download it (§2). One of the row's three bounded inputs is
  therefore carried over from the 2026-09-17 log rather than re-run.
- **Packs with `<patch>` stay out.** Five of the ten installed packs — half the
  local corpus, and seven of the fifteen accepted ones — are refused by
  ADR-0198 §2. The patched-ROM import is §3's follow-up slice, and this log
  says nothing about whether it will work.
- **Audio-only packs have no project shape.** 1942 is refused for having no
  `<tile>`; `mep_build.py build` also refuses a key source without one. The
  `<bgm>`/`<sfx>` lines of a pack that *does* have tiles are copied and
  compared as carried lines, but no audio was listened to, re-encoded or
  rendered anywhere in this run.
- **NES only.** All three packs are NES. Nothing here says how the importer
  reads a GB/GBC or SMS pack, and no such pack is installed to try.
- **Nothing was rendered in the emulator.** This log compares manifests and
  pixel blocks. No `headless_record` frame of an imported pack was captured, so
  "the same pixels" is a statement about the bytes the loader would read, not a
  screenshot of the game drawing them.
- **No artist opened an imported project.** Whether the split of an animated
  pattern into one cell per frame is *workable* to paint — 1 703 extra cells on
  Contra80s, the same crop appearing twice in a sheet when two conditions share
  it — is a cold-read row for a person, not something this run measured.
- **`build`'s exit code on Contra80s is still 1**, from the input's own
  dangling `<background>`. An importer user has to read the errors to see that
  none of them is theirs.
- **`scripts/mep_import.py` still does not ship in the release tools zip**
  (`scripts/tools-zip-manifest.txt`), and `docs/hd-pack-authoring.md` does not
  mention it. Unchanged from 2026-09-17 and deliberately outside this row.
- **One behaviour change reaches packs that are not imports:** an ADR-0197 §1
  authored cell now takes its trailing `<tile>` fields from the key source
  instead of `1,N`. On a recorded pack the key source says `1,N` for those keys,
  so the emitted manifest is the same — that is what the unchanged
  `test_mep_build.py` count stands for, and it is an argument, not a
  measurement over recorded packs in the wild.
