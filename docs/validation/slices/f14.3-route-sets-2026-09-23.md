# F14.3 — route sets declared for the four stage dirs that lacked one (2026-09-23)

Slice F14.3, "Declare route sets for the four stage dirs that lack one",
accepted with F14.1–F14.2 by the user on 2026-09-23: *"Sim, como recomendado
(Recommended)"*.

**Problem.** The unattended library job (`scripts/record_library.sh`, F12.10)
matches a ROM to a route set only through `scripts/stages/<game>/stage-set.json`
(the #314 rule: a set is bound to the exact dump its routes were authored on,
never to a folder name). Only `mm3/` and `zelda/` had one, so Contra, Metroid,
Zelda II and Excitebike resolved to `static` although their route scripts exist.

**Stop conditions.** (1) `record_library.sh` resolves `routes` for all six
games; (2) every kit's `--verify` is 0 lost / 0 added; (3) `library-report.md`
shows `seen %` per game. **All three hold** — evidence below.

## Findings

1. **Nine of Contra's sixteen stages are recorded from power-on.**
   `stage2-base`, `stage3-*` and `stage4-*` start from states that come from a
   `.chain.txt` (or, for `stage3-waterfall`, from a state that cannot be re-minted
   at all — see the stage README), which this job does not replay; `mint_plan`
   reports them as unserved and `record_stages.sh` runs their scripts from
   power-on. All nine landed on the **attract demo**: 2 973 retained frames and
   1 058–1 135 silhouettes each, identical run to run. They are not the stage
   they are named for. They inflate the retained-frame total (26 757 of 49 186)
   but not `seen %`: re-running `artist_chr_kit` over the seven served stages
   only gives the same **87.6**, because `seen` is counted per surface and the
   demo shows only stage-1 art the served stages already cover. Replaying the
   chains (or skipping unserved stages) is a job change, not a manifest one, and
   is left out of this slice.
2. **`stage1-boss` and `stage1-long` start at the stage-1 entry, not where their
   scripts expect.** The longest-prefix rule pairs them with `mint-stage1`, so
   `stage1-boss.txt` (written for the wall state `stage1-boss.mss`) plays from
   the start of stage 1: 18 silhouettes instead of the 69 poses F9.22 measured
   at the wall. `stage1-long` retains exactly what `stage1-run` does (2 198
   frames, 138 silhouettes). Same class as finding 1.
3. **Contra's `seen %` of 87.6 is page-granular** (16 CHR pages), so on a CHR
   RAM game it says little about which stages the kit covers; finding 1 is
   invisible in it.
4. **`zelda/`'s own history points at another dump.** The F9.22 golden run's
   `runs/golden-20260912/zelda/Zelda.nes` is the library dump (whole-file
   `3CDFA4F2…`, No-Intro `B6643CE5…`), while `zelda/stage-set.json` pins
   `roms/Zelda.nes` (`BE2F5DC8…`), the dump F12.10 verified. The pin is correct
   by the README's rule (declare what you ran), and this run verified it again;
   the library dump is simply not declared. Not changed here.
