# F12.6a — lint validates authored conditions against recorded routes (2026-09-19)

Scope and stop rule live in the PRD (Part A §4, Phase 12, row F12.6a) and the
decision in ADR-0197 §1–§2. The stop rule: *the report names the frame and route
of every failure*, on a bounded input of Contra routes and a sheet carrying
three authored conditions. This log is the evidence for that, and it also
records one deviation from the row and one fact about the routes that the row
assumed otherwise.

No emulator was run for this slice. The recordings are the ones the F9.25 Contra
matrix already produced; nothing here re-records or re-renders.

## Inputs

- **Pack**: `runs/f918v-20260915/contra/unpainted-full`, copied to a scratch
  folder and given a `conditions` block on `textures/sheets/metatiles.json`.
  The pack itself is unmodified in the repository.
- **Routes**: the six grid dumps of `runs/f925-20260915/contra/map/*/grid.txt`
  (`clean-300s`, `coverage-barrier`, `coverage-lives`, `nav-stage2`,
  `nav-stage3`, `nav-stage4`) — 985 MB of text, 22 772 retained frames standing
  for 85 429 played.
- Host: MacBookAir10,1 / Apple M1, 8 cores, 16 GB, macOS 26.6.2. Whole run:
  about 11 s per route, 70 s for the six.

## The three authored conditions

Each is attached to a real metatile cell of the pack's own sheet, and each key
was chosen by first asking the recording where that key is actually drawn — so
the conditions say something the evidence can agree or disagree with, rather
than being shaped to pass.

| name | type | attached to | the author's claim |
|---|---|---|---|
| `scoreGlyph` | `tileAtPosition` 216,216 | metatiles cell 48 | this glyph is what the score line draws at that screen cell |
| `openToTheRight` | `tileNearby` +8,0 | metatiles cell 37 | this piece is drawn with open backdrop one cell to its right |
| `blink` | `frameRange` 4,2 | metatiles cell 60 | this piece blinks on two frames of every four |

Every failing row carries a frame number and a cell, which is the stop rule.
Three things in the table are worth reading rather than skimming:

- **No condition held everywhere.** Three plausible, hand-written claims, and
  the recording contradicts all three in part. That is the slice's point: the
  report is the first thing in the toolchain that can tell an author their
  condition is wrong before a player sees it.
- **`openToTheRight` fires far more often where it was not attached than where
  it was** — 714 006 unintended hits against 2 263 intended, on `clean-300s`.
  A `tileNearby` describes a pattern, not a place, and "with open backdrop to
  the right" is true of most of the sky. This is exactly the failure mode
  ADR-0197 §2 asks the report to surface by name.
- **`blink` reports no phase offset that would hold throughout.** A recording
  numbers its own retained frames; the emulator evaluates `FrameNumber % 4 >= 2`
  against its global counter (ADR-0189 §4). The report says which offsets would
  make the condition hold on every retained frame, and for this route there is
  none — so the author cannot fix it by shifting the phase.

## A fact about the bounded input the PRD row did not anticipate

`scoreGlyph`'s `held` is **539 on all six routes**, and `blink`'s counts are
identical to the digit on all six, while the `failed` counts diverge. That is
not a bug in the evaluator: the six routes share their opening. Comparing the
decoded key grids of `clean-300s` and `nav-stage4` frame by frame, **249 of the
first 300 retained frames are identical**, cell for cell. The dumps differ
byte-wise only because shape ids are interned per run.

Four of the six also stop at exactly 4 096 retained frames, which is the
recorder's retention cap, not the end of the run.

So "six recordings" is less independent evidence than it sounds: the holds come
from the shared prefix and only the failures come from where the routes part.
Anyone sizing future route coverage off this matrix should know that.

## Deviation from the row: `spriteNearby`

The F12.6a row lists `spriteNearby` among the types lint evaluates. **It is
reported `not evaluable` instead**, alongside `memoryCheckConstant`:

```
  nearThePlayer  (spriteNearby, textures/sheets/metatiles.json, 4 key(s))
    <condition>nearThePlayer,spriteNearby,8,0,FEE0E0FEE0E0FE00...,0F102816
    not evaluable: the recorded sprite stream carries vocabulary indexes, not
    tile data, so a 32-hex key cannot be matched against it (ADR-0197, F12.6b)
    not evaluable is never a pass.
```

`MESEN_OAM_STREAM_DUMP` writes `vocab.Find(key)` — an index into the recording's
own vocabulary, not the 16 pattern bytes a `<condition>` line carries. Matching
one against the other needs the dump format to change, and ADR-0197's
Consequences put dump-format work in F12.6b. Evaluating it against an index
would mean comparing two different things and calling the answer a verdict,
which is worse than declining, so it declines and says why.

`not evaluable` is never counted as a pass: the verdict holds zero in both the
`held` and `failed` columns and the report prints that line under it. The same
is true of `memoryCheckConstant`, `ppuMemoryCheck*`, `positionCheck*` and
`originPositionCheck*`, each with its own reason rather than a shared shrug.

## What the automated suites cover

- `python3 scripts/test_mep_conditions.py` — **25/25**. The evaluation cases are
  written from the C++ expressions in `Core/NES/HdPacks/HdPackConditions.h`
  (`PixelOffset = (y*256)+x`; `tileNearby` relative to the drawn tile;
  `FrameNumber % OperandA >= OperandB`), not from the Python, because a report
  that disagrees with the emulator is worse than no report. Also: the syntax a
  sheet may carry, a CHR-index key refused with its reason, the `tileNearby`
  8-pixel alignment `HdPackLoader` enforces, and the ADR-0189 §3 bare twin.
- `python3 scripts/test_mep_build.py` — **80 PASS**, four of them new: the
  authored definition reaches `hires.txt` once and verbatim, the conditioned
  cell emits its rule *and* the unconditional twin (#256), a cell that named no
  condition stays unconditional, and the definition precedes its first use, as
  `HdPackLoader` needs.
- `make doc-checks` — exit 0, including the `mep_build.py` ceiling at its new
  1945 (ADR-0137, seventh amendment).

## Honest limits

- **One game, one console, one pack.** Contra, NES, CHR RAM. Nothing here says
  how the report reads on a CHR ROM game, where keys are indices.
- **The three conditions are mine, not an artist's.** They are shaped like
  claims an author would make and were written before the routes were consulted
  for anything but the key positions, but no artist wrote or read them. Whether
  this report is *useful* to an author is the cold-read row this phase reserves
  for a person.
- **`spriteNearby` is deferred, not solved** (above).
- **The routes overlap** (above), so six rows are not six independent tests.
- **No Core code changed and no pack was rebuilt into a game.** The build-side
  round trip is asserted by the unit suite against a synthetic pack; this log
  does not show an authored condition rendering in the emulator.

## Reproduction

```sh
# three authored conditions on a copy of the recorded pack
python3 - <<'PY'
import json, pathlib
p = pathlib.Path("<pack>/textures/sheets/metatiles.json")
d = json.loads(p.read_text())
d["conditions"] = [{"name": "blink", "authored": True,
                    "line": "<condition>blink,frameRange,4,2"}]
d["cells"][60]["condition"] = "blink"
p.write_text(json.dumps(d, indent=2))
PY

python3 scripts/mep_lint.py <pack> --routes runs/f925-20260915/contra/map/*/grid.txt
```

The pack folder must come first; `--routes` consumes every path after it. A
route is a grid stream written by `MESEN_SHEET_GRID_DUMP` on a run that reached
gameplay (`docs/remastering-a-game.md`); a file that is not one is skipped with
its reason rather than failing the run.
