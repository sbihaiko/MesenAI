### Condition 2 in detail (F12.18)

Method, reusing the F12.18 log's approach (stdlib, ~150 lines, not
versioned — `compare_oam.py` in the scratchpad): parse `oam.txt`'s `K`
(shape id → tile hex) and `P` (palette id → palette hex) dictionaries and its
per-frame `shape,x,y,palId` entries; parse `sprites.json`'s cells (and their
aliases) into a `(tile, palette) → node` map; for each run-cycle pose, take
the frame with the largest `held` run from `tracks.txt` (not necessarily the
first — pose001's first appearance is a 1-frame transition at frame 0, not
representative of the standing pose the phase actually draws); resolve every
OAM entry on that frame to a node, greedily match each pose tile to the
closest unclaimed same-node OAM entry (relative to the cluster's bounding
box), and compare to the pose's `(px, py)`.

One method wrinkle, not a pack defect: an all-zero (fully transparent) tile
is visually identical under any palette, and this pack's vocabulary records
only one `(tile, palette)` variant for it. A naive `(tile, palette)` lookup
therefore fails to resolve a blank OAM entry drawn with a different palette
id than the one the vocabulary happened to record. Fixed by matching blank
tiles on tile identity alone (any palette) — after that, all 11 poses
(pose000, 001, 002, 004–011) matched 100% of tiles with 0 px error.

## Surprises

- `artist_kit.py --verify` **fails** (`0 lost, 1662 invented`) when run on a
  pack that already had the F12.18 painted round-trip applied to it (the
  `full` copy) — not because of a linker or offset regression, but because
  the painted magenta tile creates keys the tool's control rebuild doesn't
  expect. Confirmed by running the identical `artist_kit.py --verify` on the
  unpainted `full2` copy of the same recording: `0 lost, 0 invented, PASS`.
  This is a testing-order artifact of doing the round-trip test and the kit
  regeneration on the same pack copy, not a defect in either tool; recorded
  here so a future run doesn't rediscover it as a false regression. No bug
  filed — it is a sequencing note, not a reproducible tool defect.
- The re-record's tile count (292) is not byte-identical to the F12.18 log's
  290, because the two logs' bounded input differs (70 s vs 61 s driver, and
  a different binary). The stop condition only requires 0 invariant
  violations, which both counts satisfy.
