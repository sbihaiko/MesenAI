# F12.6b — the recorder retains internal RAM (2026-09-19)

Scope and stop rule live in the PRD (Part A §4, Phase 12, row F12.6b) and the
decision in ADR-0197 §3, which was settled as **option (b)**: the fixed
`$0000`–`$07FF` window, on every retained frame, independent of any loaded
pack. The stop rule has two halves — *a `memoryCheckConstant` from Contra80s is
evaluated on a recorded route and the verdict matches a manual check on three
frames*, and *the per-recording cost is measured on a 60 s Contra route before
any doc quotes a number*. This log is the evidence for both, in that order:
the cost was measured first, against a baseline binary built from `main`, and
only then written into ADR-0197 and the PRD.

F12.6a left two things open. One of them closes here (`memoryCheckConstant`).
The other, `spriteNearby`, does **not** — see "Honest limits".

## What changed

- `MesenSheets::kRetainedRamSize = 0x800` and an inline `RamDumpLine`
  (`Core/NES/HdPacks/TileSheetTypes.h`). The encoder is host-free and inline
  because `HdPackBuilder.cpp` is not in the `core-unit-tests` link set, so
  that is the only place its wire form can be tested.
- `HdPackBuilder` keeps a `_gridRam` plane, flat, 2 KB per retained frame and
  parallel to `_gridFrames` by construction. `NesConsole` hands
  `OnFrameEnd` the console's own internal RAM at the frame boundary
  `HdNesPpu::OnBeforeSendFrame` samples a pack's watched addresses at.
- `WriteGridDump` gains one line kind: `M <4096 hex>`, **once per retained
  frame**, on its first repeat. The rest of the frame body is re-emitted per
  collapsed duplicate; the memory of a frame that held still is the memory of
  the frame it collapsed into, and 4 KB of hex per *played* frame would be six
  times the file for no further evidence.
- `scripts/mep_conditions.py` parses `M`, evaluates `memoryCheckConstant`
  against it, and refuses — by name and with a reason — an address outside the
  window and a recording that has no memory plane.
- `scripts/artist_map.py` skips `M` explicitly. It had to: an unknown line
  falls through to that reader's cell parser and takes the whole dump with it.

`make capture-tool` was re-run. `scripts/headless_record` itself is unchanged
(`6e3b46657c81ba3af97fc96ffd8590ecedff2daeb6a4ada9c7cbf902d9560e15`, the same
sha256 before and after — the harness source did not move); the change is in
the core it links, `InteropDLL/obj.osx-arm64/MesenCore.dylib`,
`1d19224631e031af5b6cb3771cf0d424a13699d8915674dd468d2dd81e8a12e4`. The
ADR-0169 viewer wire format was **not** touched.

## The route, and the state it starts from

`.mss` files are not versioned, so the state was minted first
(`scripts/stages/README.md`):

```sh
scripts/headless_record roms/Contra.nes 30 out/mint bootstrap hdpack-off \
  input=scripts/stages/contra/mint-stage1.txt save-state=out/stage1-run.mss
MESEN_SHEET_GRID_DUMP=$PWD/grid.txt scripts/headless_record <fresh>/Contra.nes 60 out/rec \
  bootstrap hdpack-off input=scripts/stages/contra/stage1-long.txt \
  state=out/stage1-run.mss
```

The ROM is copied into a fresh folder per run on purpose: the MEP bootstrap
records into `<rom>/auto` only once, and it is the bootstrap that turns on the
builder's screen capture — which is what fills the grid stream at all. A
second run in a folder that already has `.bootstrap` produces a pack and no
grid dump, which is a trap worth writing down.

Route: 60 s of `stage1-long.txt` from `stage1-run.mss`, 3 606 emulated frames,
**607 retained** standing for **3 597 played**, 123 shapes.
Host: MacBookAir10,1 / Apple M1, 8 cores, macOS 26.6.2.

## The cost, measured

Two runs of the same route on each binary, same machine, nothing else running.
The baseline is the tree at `2724d20f` built the same way, before any of the
change above.

| | grid.txt | wall (`time -p real`) | emulator's own counter |
|---|---|---|---|
| before, run 1 | 38 777 814 B | 15.02 s | 13.7 s |
| before, run 2 | 38 777 814 B | 15.03 s | 13.7 s |
| after, run 1 | 41 265 907 B | 16.16 s | 14.0 s |
| after, run 2 | 41 265 907 B | 14.84 s | 13.6 s |

- **Size: +2 488 093 B, +6.42 %.** Exactly 4 099 B × 607 retained frames
  (`M `, 4 096 hex characters, newline) — the arithmetic closes, so nothing
  else grew.
- **Wall clock: inside run-to-run noise.** The two "after" samples straddle
  the two "before" ones (14.84 s and 16.16 s against 15.02 s and 15.03 s) and
  the emulator's own counter says 13.6/14.0 s against 13.7/13.7 s. Four
  samples is not a benchmark, and the honest statement is not "it is free" but
  "the cost did not rise above the variance of this measurement". The size
  number is exact; the time number is not.

Had the `M` line been written per *played* frame instead of per retained one,
the same route would have cost 3 597 × 4 099 B = 14.7 MB, +38 %. That is the
whole reason for the "first repeat only" rule.

## The stop rule: four real Contra80s conditions on a recorded route

Every `<condition>` line below is copied verbatim out of
`roms/spike-contra80s/mesen-home/HdPacks/Contra (USA)/hires.txt` — they are the
community author's, not mine. That pack uses `memoryCheckConstant` **486**
times, and every one of its addresses is inside the retained window (the
highest is `$0191`), so the window ADR-0197 §3 fixed covers the whole of the
most prolific hand-author's memory vocabulary for this game.

They were attached to four cells of the recorded pack's own
`textures/sheets/metatiles.json` and replayed with
`python3 scripts/mep_lint.py <pack> --routes <run>/grid.txt` (exit 0 — a
report, not a gate):

| condition | line | verdict | held | failed |
|---|---|---|---|---|
| `BaseDoorFix2` | `memoryCheckConstant,30,==,0` | **always held** | 4 777 | 0 |
| `screen01` | `memoryCheckConstant,64,==,01` | **mixed** | 6 081 | 13 697 |
| `stage5` | `memoryCheckConstant,30,==,04` | **never held** | 0 | 4 777 |
| `deathstarblinkstart` | `memoryCheckConstant,191,==,F0` | **never held** | 0 | 4 777 |

These are the three states the report can distinguish, and each is the right
one for a stage-1 route: `$0030` is Contra's stage byte and it is 0 throughout,
so "stage 5" never holds and `BaseDoorFix2`'s `$30 == 0` always does; `$0064`
is the screen index, which is 0 for 478 retained frames and 1 for 129, so
"screen 01" is genuinely mixed. Counts are per *drawn instance* of the
conditioned key, not per frame, which is why they differ between rows.

### The manual check — three frames, twelve comparisons

Read straight out of the `M` line at character offset `2 * address` (no
decoder), compared by eye with the operator in the `<condition>` line, then
against what the evaluator decided for that same frame:

| frame | condition | addr | hex in the `M` line | op | const | by hand | evaluator |
|---|---|---|---|---|---|---|---|
| 0 | `BaseDoorFix2` | `$0030` | `00` | `==` | `00` | True | True |
| 0 | `screen01` | `$0064` | `00` | `==` | `01` | False | False |
| 0 | `stage5` | `$0030` | `00` | `==` | `04` | False | False |
| 0 | `deathstarblinkstart` | `$0191` | `00` | `==` | `F0` | False | False |
| 314 | `BaseDoorFix2` | `$0030` | `00` | `==` | `00` | True | True |
| 314 | `screen01` | `$0064` | `01` | `==` | `01` | **True** | **True** |
| 314 | `stage5` | `$0030` | `00` | `==` | `04` | False | False |
| 314 | `deathstarblinkstart` | `$0191` | `00` | `==` | `F0` | False | False |
| 606 | `BaseDoorFix2` | `$0030` | `00` | `==` | `00` | True | True |
| 606 | `screen01` | `$0064` | `00` | `==` | `01` | False | False |
| 606 | `stage5` | `$0030` | `00` | `==` | `04` | False | False |
| 606 | `deathstarblinkstart` | `$0191` | `00` | `==` | `F0` | False | False |

Twelve comparisons, twelve matches. Frame 314 is the first retained frame on
which the camera has reached screen 1, which is why it is one of the three:
two frames where everything is false prove less than one where something
flips.

### And the plane really is the console's RAM

Reading a byte out of a file the same program wrote is a closed loop, so one
independent check: frame 0 of the route is the frame the run resumes on, and
the state it resumed from can be read by a completely different parser,
`scripts/mss_ram.py`, over the `.mss`.

```
mss_ram.py stage1-run.mss:  $0030=0 $0064=0 $0191=0 $0032=2
grid.txt frame 0 M line:    $0030=00 $0064=00 $0191=00 $0032=02
```

Four addresses, two unrelated readers, same bytes — the window is at the right
offsets and holds the console's real memory, not an aliased copy of something
else.

### A recording made before this slice

The same pack against the *baseline* run's dump:

```
before1: not evaluable — the recording retains no memory stream — it was made
         before F12.6b (ADR-0197 §3); re-record it to validate a memory condition
  not evaluable is never a pass.
```

Old dumps parse unchanged and decline by name, which is the ADR's second
limit. The first one — an address outside the window — is covered by the unit
suite (`$6000` reports *"outside the retained `$0000`-`$07FF` window"*), not by
this route, because Contra80s never writes such a condition.

## What the automated suites cover

- `python3 scripts/test_mep_conditions.py` — **34/34** (was 25/25; nine new
  cases). The evaluation cases are written from
  `HdPackMemoryCheckConstantCondition::InternalCheckCondition`, including the
  one detail that is easy to get backwards: the mask is applied to the byte
  read from memory and **not** to the constant. Also: the loader's hex
  operands (`30` is `$0030`, not 30), every operator, the out-of-window
  refusal, the pre-F12.6b refusal, per-instance counting, and a short or
  malformed `M` line dropped rather than half-read.
- `make core-unit-tests` — **887/887** (was 877; ten new checks in three new cases). `RamDumpLine` is
  fixed-width upper-case hex with the byte at address A at characters
  2A/2A+1, pads rather than shortens on a short or absent window, and clips a
  wider one (FamicomBox's `$2000`) to the ADR's range.
- `python3 scripts/test_mep_build.py` — **80 PASS**, unchanged: the build side
  did not move in this slice.
- `dotnet test UI.Tests/UI.Tests.csproj` — **498/498**, untouched by this
  slice but run because a Core signature moved.
- The whole `scripts/test_*.py` sweep — **45 suites, all exit 0**, which is the
  check that matters for `artist_map.py`: it reads the same dumps and would
  have died on the new line kind if it had not been taught to skip it.
- `make doc-checks` — exit 0, with `HdPackBuilder.cpp`'s ceiling at its new
  2282 (ADR-0137, eighth amendment; it had five lines of headroom and now has
  none).

## Honest limits

- **`spriteNearby` is still `not evaluable`, and this slice did not change
  that.** F12.6a's log named the OAM dump's vocabulary indexes as the blocker
  and pointed at "F12.6b's dump-format change"; the change F12.6b actually
  makes is to the *memory* plane, which is what ADR-0197 §3 decides and all it
  decides. Serving `spriteNearby` needs the OAM stream to carry tile data, a
  different format change with a different cost, and widening scope to it here
  would have been a decision nobody took. It remains open.
- **`memoryCheck` (two watched addresses) is also still declined.** It would
  read the same window and is a few lines away, but ADR-0197 §3 is written
  about `memoryCheckConstant` and the stop rule says so. Its `not evaluable`
  reason now states that honestly instead of claiming no memory is retained.
- **One game, one console, one route, one pack.** Contra, NES, CHR RAM, 60 s
  of stage 1, and the conditions were attached to a *recorded* pack's sheet,
  not to Contra80s' own art. Nothing here says how the cost scales on a longer
  route or a game with a busier screen — although the size cost is
  arithmetically 4 099 B per retained frame, so it scales with retention and
  not with play time.
- **The wall-clock number is four samples, not a benchmark.** It says the cost
  did not rise above the noise of this measurement; it does not say the cost
  is zero.
- **The route never left stage 1.** `$0030` is 0 on all 607 frames, so no
  condition that tests a *different* stage could have held; `screen01` is the
  only row where the byte actually changes. A route that crosses a stage
  boundary would be better evidence and was not recorded.
- **Nothing was rendered.** No pack was built into a game and no frame was
  drawn with a `memoryCheckConstant` gating it; this log shows the report
  agreeing with the recording, not the emulator agreeing with the report at
  render time. The emulator's own expression is mirrored in unit tests, which
  is the second-best thing and not the same thing.
- **The memory of a collapsed frame is the memory of the frame it collapsed
  into.** A game whose screen holds still while its RAM changes — a paused
  countdown, a fade — retains one `M` line for that whole stretch. The
  retention cadence is the grid's, and this slice did not change it.

## Reproduction

```sh
# 1. mint (never version the .mss)
scripts/headless_record roms/Contra.nes 30 out/mint bootstrap hdpack-off \
  input=scripts/stages/contra/mint-stage1.txt save-state=out/stage1-run.mss

# 2. record, into a ROM folder that has never been bootstrapped
mkdir -p out/run && cp roms/Contra.nes out/run/
MESEN_SHEET_GRID_DUMP=$PWD/out/run/grid.txt scripts/headless_record \
  out/run/Contra.nes 60 out/run/rec bootstrap hdpack-off \
  input=scripts/stages/contra/stage1-long.txt state=out/stage1-run.mss

# 3. author four real Contra80s conditions onto the recorded sheet
python3 - <<'PY'
import json, pathlib
p = pathlib.Path("out/run/Contra/auto/textures/sheets/metatiles.json")
d = json.loads(p.read_text())
conds = [("BaseDoorFix2", "<condition>BaseDoorFix2,memoryCheckConstant,30,==,0", 12),
         ("screen01", "<condition>screen01,memoryCheckConstant,64,==,01", 20),
         ("stage5", "<condition>stage5,memoryCheckConstant,30,==,04", 30),
         ("deathstarblinkstart",
          "<condition>deathstarblinkstart,memoryCheckConstant,191,==,F0", 40)]
d["conditions"] = [{"name": n, "authored": True, "line": l} for n, l, _ in conds]
for n, _, c in conds:
    d["cells"][c]["condition"] = n
p.write_text(json.dumps(d, indent=2))
PY

# 4. the report
python3 scripts/mep_lint.py out/run/Contra/auto/textures --routes out/run/grid.txt
```
