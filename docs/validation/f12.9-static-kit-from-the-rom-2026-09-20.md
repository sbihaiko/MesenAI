# F12.9 — a kit projected over the ROM alone, with no play session (2026-09-20)

Scope and stop rule live in the PRD (Part A §4, Phase 12, the day-one block, row
F12.9); the decision is ADR-0219, accepted 2026-09-20 and implemented in the same
change. The row re-measures **"faster on day one"** at its floor: seconds instead
of a play session. What it does *not* claim is usefulness — a static kit has no
figure, no scenery and no stage map, because those come from what a run observed
and nothing was observed. This log is the evidence for the row's four stop
conditions and for two things measured beside them.

## Stop condition 3 — one painted cell, pixel-exact, by reopening the ROM

The full loop, not a shortcut: paint in the **kit**, copy `chr/` into the pack,
build, install as `mesen-home/HdPacks/smb/`, render 3 s of SMB from power-on.

- Cell painted: **slot 58 of `Chr_00_0`** (bank 0, the sprite pattern table),
  solid `#00FF00`, chosen because a single-run probe (a unique colour per cell)
  showed cells 55, 58, 79 and 252 of that bank on screen at frame 180, and 58 is
  the one that appears exactly once.
- Baseline and painted screenshots, 1024×960, differ in **exactly 1 024 pixels**
  — one 32×32 block at (160, 772), which is one tile at scale 4.
- **Every** differing pixel is `#00FF00`. Nothing else on the frame moved.

## Stop condition 4 — ROM to `kit/` under 10 s

| game | wall time | pages |
|---|---|---|
| SMB | **0.51 s** | 2 |
| Mega Man 3 | **5.69 s** | 32 |

Measured with `/usr/bin/time -p` on the dev machine (Apple silicon, Python
3.12), cold output directory each time.

## What the runs found

1. **The first Mega Man 3 run took 10.13 s and would have failed the row by 1.3 %.**
   The cause was the blank canvas each static page starts as: 32 pages × two
   images × 512×512 px is 16.7 M `set()` calls writing a colour that the ROM fill
   then overwrites. Building the canvas as one buffer took the run to 5.69 s. The
   number is in the row because it is the kind of budget a ratchet protects: the
   slice was *at* its stop condition, not comfortably inside it.
2. **A static pack matches 100 % of background tiles on both games.** The
   recorder's debug line reports `bg tile match rate: 3686400/3686400 (100%)` for
   SMB and `3571200/3571200 (100%)` for Mega Man 3, over the title screens. This
   is ADR-0210's claim observed at run time rather than argued: the shape set of a
   CHR ROM game is complete in the file, and `defaultTile = Y` is the per-rule
   palette wildcard, so a pack built with no recording at all still covers every
   background tile the game draws. It says nothing about *sprite* coverage or
   about organisation.
3. **A sibling pack silently wins.** The first render loaded
   `20 image(s)` and matched 6 % — it had found the SMB folder's own `auto/`/`mep/`
   pack next to the ROM through the bootstrap convention, not the pack under test.
   Copying the ROM to a scratch directory is what makes the measurement about the
   static pack. This is the same shape as the trap recorded for
   `EnhancementPacks/`, and it cost the first two runs.
4. **The palette in the page is a placeholder and the page says so.** Every
   static page is drawn under `0F001030` — the value `Bank.fill_palette()` already
   returns when no cell votes — and every rule is `Y`, so the drawn colours are for
   reading, never a claim. `ARTIST.md`'s first line says no play session happened
   before it says anything else.

## F12.10's path (d), closed by the same change

`record_library.sh` resolved a ROM matching no route set, no `.bk2` and no entry
script to `static` and then produced nothing — the gap F12.10's own log states.
It now projects the static kit instead. Run on a one-ROM library holding SMB:

```
| ROM | driver | status                                                  | seen % | kit --verify |
| smb | static | static kit from the ROM alone - nothing was seen in play |    0.0 |            0 |
```

The kit is written with `ARTIST.md`, `kit.json` and `chr/`, `--verify` reports 0,
and `seen %` is **0.0** rather than blank — which is the honest number and the
reason the column exists. A CHR RAM game on the same path still gets no kit: the
generator refuses it and its refusal becomes the row's status.

## What this does not deliver

- **Nothing for the 7 CHR RAM games.** `--static` refuses them, naming
  `scripts/mep_import.py index` (ADR-0210 §3, F12.12) as the only static source of
  shape. The refusal is stronger than the recorded path's: with no recorded tiles
  there is no PRG block to pin, so not one tile could be recovered.
- **No organisation.** No `sprNNN` figure, no scenery group, no stage map. Those
  are observations, and the kit carries none.
- **The ROM-SHA-1 pin is disabled by construction on this path**, as ADR-0219's
  Consequences names: there is no `<supportedRom>` to pin against, so `--rom` is
  the whole of the input. The manifest records the ROM's own sha1 and every cell
  says `seen: false`.

## Reproduce

```
python3 scripts/artist_chr_kit.py /tmp/nothing --rom <rom>.nes --static --out /tmp/kit --verify
mkdir -p /tmp/pack/textures && cp -R /tmp/kit/chr /tmp/pack/textures/
python3 scripts/mep_build.py build /tmp/pack     # N rules, all defaultTile=Y, 0 errors
python3 scripts/mep_lint.py /tmp/pack            # 0 errors
```

`--verify` runs the same build in a temporary copy and prints the rule count
against the ROM's CHR tile count. It is the static substitute for ADR-0183 §4's
round-trip, which is vacuous here: there is no recording to lose a key against.
