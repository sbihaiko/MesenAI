# F12.14 — the OAM stream dump is self-describing, and lint evaluates the sprite conditions (2026-09-22)

ADR-0222, option A. The stop conditions were the F12.6a bounded input: the
Contra pack's authored `spriteNearby` line goes from `not evaluable` to a
verdict on the 60 s stage-1 route, a two-address `memoryCheck` reports a
verdict against the same `M` plane, and a unit test pins a synthetic OAM
frame pair. All three hold; the numbers are below.

## What changed

- **Core.** `MesenSheets::OamEntry` gained `PaletteId Palette` — the sprite's
  palette word interned through the same `HdPackBuilder::PaletteIdFor` table
  the grid stream's `P` lines spell — and `operator==` (hence
  `OamFrame::SameEntries`) compares it, so a frame that only recolours a
  sprite is retained as its own frame. `RecordSprite` fills it from the
  `HdPpuTileInfo::PaletteColors` the PPU hands over. The
  `MESEN_OAM_STREAM_DUMP` writer moved out of `HdPackBuilder.cpp` into the
  host-free `MesenSheets::WriteOamStreamDump` (`TileSheetTypes.h`) and writes
  `K <id> <32 hex tile data> <8 hex palette>` on a shape's first sight,
  `P <id> <8 hex palette>` on a palette word's first sight, and per frame
  `<frame> <repeat> <port1> <port2>` followed by `<shape>,<x>,<y>,<pal>` —
  `shape` is `OamEntry::Shape`, the recorder's `ShapeId`, no longer
  `vocab.Find(key)`. `HdPackBuilder.cpp` stays at 2 427 lines under its
  2 428 ceiling (the palette table is now `PaletteColorTable()`, shared by
  both dumps).
- **ADR-0169 wire format: not changed.** `Utilities/LiveRecordFormat.h` and
  `sprites.json` carry the raw 64 OAM entries (`[y, tile, attr, x]`) plus the
  32 bytes of palette RAM, not `OamEntry`s; the sprite palette is already on
  the wire as the attribute's palette bits resolved through palette RAM.
  `make capture-tool` was re-run only so the headless recorder links the
  rebuilt core. ADR-0169 carries a one-line amendment saying so.
- **Lint.** `scripts/mep_conditions.py` gained `parse_oam_dump`,
  `OamFrame`/`OamStream`, and a `Route.oam` read from `oam.txt` beside a
  route's `grid.txt`. `spriteNearby`, `spriteAtPosition`, `positionCheckX/Y`
  and `originPositionCheckX/Y` are evaluable; `memoryCheck` reads both
  operands off the `M` line exactly as `memoryCheckConstant` reads one. The
  "vocabulary indexes" reason strings are retired; a pre-F12.14 dump (no `K`
  lines) reports `OAM stream carries no tile data`. Two parser fixes came
  with it: `positionCheck*` operands are read as decimal (the loader uses
  `std::stoi`, not `FromHex`), and the `ignorePalette` field accepts the
  loader's `Y`/`YES`/`TRUE`/`1` — `Y` is what `ToString` itself writes, and
  the old parser only accepted `true`/`1`/`yes`.

## The route

ROM: `Contra (1988) (Konami).nes`, 128 KB, UNROM, CHR RAM — the user's
library copy. (The `roms/spike-contra80s/live-validate-test/Contra (USA).nes`
in the repo is a 32 KB NROM test ROM: it boots to a static screen, retains no
grid frame and writes no dump; the first attempt against it produced an
empty run and is not counted.) The `.mss` was minted first, never versioned,
and the recording ran into a ROM folder that had never been bootstrapped —
both traps `f12.6b-recorder-retains-internal-ram-2026-09-19.md` names.

```sh
scripts/headless_record out2/Contra.nes 30 out2/mint bootstrap hdpack-off \
  input=scripts/stages/contra/mint-stage1.txt save-state=out2/stage1-run.mss
MESEN_SHEET_GRID_DUMP=$PWD/out2/run/grid.txt MESEN_OAM_STREAM_DUMP=$PWD/out2/run/oam.txt \
  scripts/headless_record out2/run/Contra.nes 60 out2/run/rec bootstrap hdpack-off \
  input=scripts/stages/contra/stage1-long.txt state=out2/stage1-run.mss
```

60 emulated seconds of `stage1-long.txt` from `stage1-run.mss`: 5 411
emulated frames (1 804 to 5 410), 17.0 s of wall clock under
`caffeinate -dimsu`.

|---|---|---|---|---|
| grid (`grid.txt`) | 607 | 3 597 | 123 shapes | 43 762 868 B |
| OAM (`oam.txt`) | 2 217 | 3 597 | 166 `K`, 4 `P` | 375 634 B |

The two streams retain the same 3 597 played frames, so
`Route.oam_aligned` is true and background keys are joined to the sprites of

The most frequent sprite key — the player, 1 221 entries under palette
`FF303828` for each of its four body tiles — is

1 221 appearances is `017E002000E00000FFFEC0E0E0E00000` (the lower half of an
8x16 sprite). Nothing is ever exactly 8 px to its right.

Stop condition 1 — the `nearThePlayer,spriteNearby,…` line reports a
verdict (`never held`), not `not evaluable`. Stop condition 2 — both
two-address `memoryCheck` lines report `mixed` from the same `M` plane
F12.6b measured. The pair `playerBelow` / `playerBelowWrongColour` is the
positive and negative control: the same offset and tile data with the
recorded palette holds on every one of the player's 1 221 appearances, and
with a palette the recording never drew it holds on none — that is the
colour half ADR-0222 says option B would have left unresolved. The
`nearThePlayer` metatiles condition is a claim the recording disagrees with
(nothing is ever 8 px right of the player's top tile), which is exactly the
report ADR-0197 §2 promised.

A note on the instance counts: a background key's sprite condition is
counted once per (grid frame, cell, overlapping OAM frame), since a grid frame
that held still for `n` played frames may overlap several OAM frames — so the
metatiles rows count tens of thousands where the sprite-sheet rows count one
per sprite. The report says which kind it counted through "first failure:
frame N at cell (c,r)" versus "first failing sprite: OAM frame N at (x,y)".

## Honest limits

- **One game, one route, one recording.** Contra, CHR RAM, stage 1. The
  join rule (`oam_aligned`) held here because every retained frame of this
  route drew both background and sprites; a route through a screen with
  sprites disabled while the background draws will not align, and lint will
  say so rather than evaluate a background key against the wrong frame.
  Whether that refusal is frequent on real routes is unmeasured.
- **The mirrored offset sign is not modelled.** The recorder bakes OAM flips
  into the interned shape (ADR-0178) and the dump does not say which shapes
  were flipped, so `spriteNearby` is evaluated with the unmirrored sign, and a
  condition naming a flipped sprite by its run-time (unflipped) key does not
  match the recorded shape. Stated in the module docstring; not solved.
- **`positionCheck*` is per pixel in the loader**; lint counts a tile as
  held only when all 8 pixels hold, so a tile the condition would split is a
  failure. `spriteNearby` is evaluated at the drawn tile's origin pixel.
- **Unintended hits are not counted for sprite conditions** (every sprite on
  screen would be a candidate); the report prints n/a.
- **Conditions authored by me, not an artist.** The `nearThePlayer` line was
  written from the OAM dump's most frequent key, not from a painter's intent;
  the F12.6a `nearThePlayer` line's full tile data is not in that log, so
  this is the same shape of claim on the same surface, not the same bytes.
- **The ADR-0179/0181 spike scripts that read `node,x,y` break** on a new
  dump, as ADR-0222 said they would; their logs are frozen and none is
  re-run here.
